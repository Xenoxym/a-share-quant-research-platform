## 发生了什么，用人话说

程序运行前检查“环境是否还是原来的环境”。我们先从项目目录保存了一张144项版本清单，再从试点目录读取它；后一张只有143项。唯一少的一项叫lhb-backtest，是本项目自己的源码包。

原因是Python查找包说明文件时会受入口路径影响：从项目目录能看见项目自己的包说明，从试点目录看不见。只查原基础库的安装目录，也得到相同143项。143项第三方发行版本完全一致；项目目录重新查询仍与原144项一致。没有证据显示基础库被更新。这是我写的环境检查口径错误，两个源码复核也没有发现，不能归咎于你的配置或授权。

程序按失败规则立即停止。下一任务会把“原基础库的143项发行元数据”和“项目自己的源码包”分开记录；这是修正核查口径，不是忽略真实依赖变更。原失败不删除，本任务不重试。

## 准备验证的六个公式是什么

例如某只股票周五收盘后，把截至当天的收盘价历史交给Qlib，得到下列六列输入。它们描述已经发生的行情，不包含随后收益；价格量纲和float32存储需与独立参考计算一致。

| 公式 | 直观含义 |
|---|---|
| $close | 当天收盘价格。 |
| Ref($close,5)/$close-1 | 五个交易日前价格相对今天的位置；跌得越多通常越大。 |
| Mean($close,20)/$close-1 | 最近20个交易日平均价格相对今天的位置。 |
| Slope($close,20)/$close | 最近20日价格趋势速度，除以当前价格消除价格单位。 |
| Rsquare($close,20) | 这段历史价格有多接近一条直线。 |
| Resi($close,20)/$close | 当前价格偏离这段历史拟合趋势的程度。 |

试点将使用同一12股×120日切片，共72组股票/公式对照，并将第61日以后的价格大幅改写，要求前60日结果保持相同。这样检查公式是否使用未来信息；通过也只是工程兼容证据。

## 真正复用成熟框架的路径

先把实际ExpressionD小样例跑通，再接到现有特征字典、缺失原因和可用时点接口。接着扩展官方Alpha158特征族、Alpha360历史序列，并保持A股板型、龙虎榜、财务、市场信息的独立分组对照；不继续无限自建同类算子。

官方Alpha158包含K线位置、趋势、波动和量价关系；Alpha360组织过去60日的价格与成交量序列。这是可借用的特征和数据组织方式，不是158个或360个已证实盈利策略。[固定发行的官方特征定义](https://github.com/microsoft/qlib/blob/da920b7f954f48ab1bb64117c976710de198373e/qlib/contrib/data/loader.py)。

官方示例默认目标是后续两次收盘价之间的变化，还包含横截面标签标准化。它与本项目计划成交开盘到下一次调仓开盘的目标不同，不能直接照搬标签、榜单收益或账户规则。[固定发行的官方训练处理](https://github.com/microsoft/qlib/blob/da920b7f954f48ab1bb64117c976710de198373e/qlib/contrib/data/handler.py)。

原始OHLC、成交量、成交额转入外部框架前，还要明确复权、股/手单位、VWAP可构建性、历史证券名单、停牌缺日和信息可用时间。第三方公式不能绕过这些检查。当前只尝试固定可信公式，不把任意LLM生成文本直接交给外部eval解析器。
