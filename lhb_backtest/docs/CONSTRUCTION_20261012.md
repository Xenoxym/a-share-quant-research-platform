# 新架构的第一批实际施工

2026-10-12。已经动手修改代码并跑过测试，不再只维护计划。**共同日期修复已完成；全部64列进入预测期的接口和合并路径已在小样本跑通。还没有新的真实模型或账户收益。**

## 这批施工服务于什么

我们要回答的是：原68项信息，加上已构造的64项组合信息，是否能让同一模型的账户收益更高，或者在相近收益下降低回撤。单个特征自己选十只股票能否盈利，并不是进入联合模型的固定门槛。

最终比较仍需相同的股票名单、日期、目标、模型参数、持仓规则和费用。RankIC用于诊断；账户年化收益、逐日最大回撤及分时期稳定性才决定是否值得继续。

## 第一件事：把所有候选放在同一段已经结束的时间里比较

举例：周五收盘后给股票排序，下一调仓日开盘买入，再下一调仓日开盘计算这一笔持有期收益。如果研究截止日还没有到卖出的那一刻，这一周就没有完整收益，所有候选都统一暂不比较。

旧程序里，有股票可选的候选会遇到“未来收益未知”；恰好缺输入、没有选到股票的候选却可能按现金零收益走完。这两类候选不应因此得到不同待遇。

现在程序先用事前声明的收益结束时间和固定截止时间，确定共同日期。尚未结束的周保留原输入及选股记录，但不进入RankIC、覆盖、冗余或收益路径。已经结束的周如果选中的股票缺收益数据，仍然报不完整，不填零、不删股票、不改变权重。

相关注册、冻结worker及反例86项通过，随后增加“未结束尾周与已结束周缺Y同时出现”的联合反例，也通过。两名独立静态复核者未发现阻断。旧结果和原64公式没有被修改。

## 第二件事：让全部64项进入预测期，不再只接旧名单里的最多8项

训练期64项公式的计算结果已经存在。新增接口复用它们的原始公式和原68项数据，只在预测期计算这些公式，随后将两段结果按“日期、股票、样本编号”合并。

| 环节 | 现在是什么状态 |
|---|---|
| 原68项完整输入 | 已有，可复用 |
| 64项训练期公式输出 | 已有，不重算公式 |
| 全部64项预测协议 | 已实现；不读取筛选晋级名单或标签 |
| 训练/预测与原列合并 | 小样本已跑通；要求完整键域与一致来源 |
| 真实预测期64列 | 原计划已登记；内存预检交接，尚未启动计算 |
| 真实132列模型与账户对照 | 未运行 |

小样本实际调用既有worker：两只股票、两个日期、两项公式，训练两行，预测两行；预测过程没有重算训练期。合并后原始列、缺失原因和时钟保持，新增两列完整覆盖四个样本。

独立复核发现并促成两项修复：检查实际准备数据计算器和字典解析实现是否与训练期相同；禁止相同公式来自不同生产者或准备数据版本却被混合。新增的实现变化、错误来源、股票重复、缺列、未来时钟和预算反例均已实际运行。中间回归189项通过；最终针对新增变化的51项全部通过。中间出现的导入及JSON表示比较错误已记录，不算通过案例。

公共能力在原`alpha_batch`登记、计算和核查路径中扩展，没有新增调度器、审批链或逐阶段恢复脚本。`alpha-feature-batch-v6`只是输入协议的版本号，并不是第六个交易模型。

## 两个实际边界

修正后的真实64项辅助诊断运行了一次，约195秒后因原50MB输出预算不足而失败。内存当时充足。局部文件与失败都保留；没有自动重跑，也没有把局部表当成有效筛选结论。这项可选诊断不会继续挡住全部特征入模。

预测启动前，物理可用内存约14.25GiB，但Windows可承诺余量约7.92GiB，低于声明的8GiB工作进程上限。主Chat在数值启动前交接了同一任务，保留计划和预算。第一次必要核查进程已退出，任务保持待领取，尚无预测实验登记或启动；不能将交接称为已完成真实预测。后续重新检查资源后使用原计划续跑，不创建重复计算。

模型容量工程已完成：配置允许明确申请最多两亿格原始输入，默认仍为3200万格；完整132列约需1.23亿格。缺失标记会将模型输入宽度翻倍，额外副本另受worker内存预算约束。108项模型与学习检查通过。Windows启动检查也已接入现有资源模块，14项检查通过；8GiB工作进程加1GiB余量，空池至少要求9GiB可承诺余量。一次独立工程复核未发现新增阻断。

## 下一步按结果推进

1. 收取当前核查和交接状态；资源允许时用原计划完成一次全部64项预测，只算预测期。
2. 合并原68项、64项训练和预测输出，准备完整132列，分开保存缺失原因及标签成熟条件。
3. 使用已完成的模型容量工程，核算转换后内存；固定同一模型，运行68与132配对比较。
4. 使用相同账户规则运行零费与含费场景，比较收益、逐日回撤、仓位、换手和年份稳定性，再决定下一方向。

这些是当前最短路径，后续模型、特征、组合及成熟组件探索仍按整体蓝图保留。资源或证据不足时缩小本批工作范围，不能擅自缩小科学比较的股票和日期。

首批施工代码已公开，GitHub完整CI通过：Windows 1783项，Ubuntu 1780项、3项跳过；包括打包与模板入口检查。[实际CI记录](https://github.com/Xenoxym/a-share-quant-research-platform/actions/runs/38303926893)。后续容量与资源修改另有上述122项本机检查，不冒充这一旧提交的CI结果。

## 已保存的第一组模型对照

先用同一个随机森林跑两次：一次读取原68列，另一次读取68＋64＝132列。两次使用同一批股票、日期、成熟标签与样本权重；均为32棵树、最大深度5、叶子至少500行、随机种子11，不调参。全为空的训练列沿用已有明确排除政策，必须报告实际保留列数。

用人话说：周五收盘后，用当时已知信息给股票打分；下一次调仓开盘选前100名，目标股票仓位98%。模型学习的收益区间是这次调仓开盘到下次调仓开盘，预处理和收益中心化只学习训练段。保留原共同主板名单，不新增小市值筛选。

这组对照计划最多训练2次、回测4次（两种输入各做零费与含费）。最后比较年化收益、逐日最大回撤、各年表现、实际仓位和换手。已有2023—2026年样本已经看过，不能宣称是全新的未见测试。随机森林固定0.5的抽样比例在列数增加后会增加每次分裂可选字段，因此结果反映整套输入扩充的效果，不能直接归因于某一列。

计划保存在本机，尚未登记或训练；原完整预测数据准备好后才执行。资源不足时不删日期或股票来凑结果。
