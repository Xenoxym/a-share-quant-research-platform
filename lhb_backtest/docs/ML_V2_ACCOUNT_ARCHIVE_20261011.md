# 旧模型分数进入新回测：实际验证与下一步

本次恢复完整完成16项v2账户存档检查，直接读取上次生成的四股票合成账户，含费与零费用两份账都通过独立核对。恢复期间没有新训练、预测、加载模型或账户模拟。它证明小型账户存档通道能工作，不能宣布收益改善，也不能宣布正式注册v2 worker的市场运行已经验证。

## 用一个周五的小例子说清楚

旧模型已给甲、乙、丙、丁保存分数。换选股规则时读取原分数，生成目标名单，再让账户逐日处理实际买卖、现金、停牌、分红与送股。产生分数的旧代码和消费分数的新代码分别保存；原训练数据、训练时间与原分数都不改。新日期没有分数时仍须正常预测，本轮“零预测”只指历史分数复用。

本次先前的R30已经产生两份小型合成账户，但测试进程被临时目录监控停止；R30R读取那两份原存档，补全所有检查，不把账户再跑一遍。

## 中间出了什么问题

R30日志只有8个通过进度点，没有最终子程序收据，整批仍然失败。可承诺余量约10GiB，所属进程峰值约0.32GiB；停止原因是pytest更新临时current别名时，严格目录扫描遇到路径消失，触发WinError2。失败、原测试和原两份账户完整保留，没有把进度点凑成正式通过数。

R30R把测试临时路径改成稳定的普通短目录，继续使用原严格文件检查。首次元数据归档的整库校验曾超过180秒；失败保留，之后关闭操作也加上操作系统所属进程时间监督，并事前明确只核本工程实际依赖和旧数据库/清单。恢复在每项完成时保存明确节点和状态；原合成存档65文件和8目录按原清单核对，恢复前后不改。原38项检查与550711行真实旧评分probe没有重跑。

## 哪些能力仍未完成

本次用的是明确标注的合成来源证明，它不是正式数据库里某个已训练模型的证明。已核小型v2准备/原生输出/存档读取；正式v2 worker的市场账户要在后续有实际研究意义的新组合实验中核对。真实持仓保留规则也尚未实现，不能据本报告判断整套研究基础设施全部完成。

四股票、短区间用于发现工程错误，不适合年化收益。本轮没有新的市场年化收益或最大回撤，之前亏损模型的结论没有改变。

## 下一步：按照实际持仓决定留谁、换谁

第一个计划设置：每周最多持有100只，新买候选来自当周评分前100；实际已持有、仍合格且排名不超过150的股票可保留。已有持仓排名151或失去资格则发出卖出意图。这里150是持仓的排名缓冲，不是小市值筛选；第一版数值预先声明，不承诺有效。

例如上周想买乙但停牌没成交，本周不能把乙算成“已持有”。想卖甲但跌停卖不掉，甲仍占实际名额；新买队列只能在实际卖出腾出名额后进入。含费和零费用账户分别依据自己的实际成交、现金与持仓决定名单，不能共用虚构的上周目标。

核对程序从成交与现金账独立重建持仓，再判断应留、应卖和新买队列；不会调用生产选择器获得“正确答案”。保留股票仍可能调股数，换股少不必然意味着费用少或收益高。

## 研究怎样保持广泛

接下来的账户实验比较同一评分/资格/时段下新规则与原Top100的含费年化收益、逐日最大回撤、年度收益、费用、换手、仓位和现金；RankIC仅作评分诊断。成熟标签滚动训练、输入表示、信息组消融、序列与股票关系、有限Alpha表达式搜索继续保留。滚动模型需要多来源评分协议；自动表达式需要有限预算、训练区内评价、完整搜索历史与真正账户终点。
