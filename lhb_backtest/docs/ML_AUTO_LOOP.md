# ML 自动推进：实际怎样运行

这次推进延续已有 ML 研究。每个阶段先保存结果、失败记录和结论，然后由两个新的只读会话分别检查方法和数据，再由另一个会话决定修订、接续不同问题、收束或暂缓。先验收现有结果，不重新训练已经完成的基准。

研究主要回答模型有没有学到选股信息。后续既定问题包括：把预测收益率改为预测同日排名是否改善选股；新股短历史、缺失特征是否影响学习；信号稳定性是否支持进一步组合实验。小市值、固定随机、每周随机和打乱标签都是对照，不是机器学习必须依赖的选股过滤。

后台循环由 `tools/ml_loop.py` 监督现有 `tools/controller.py`。每个总控仍有明确的轮数、调用数、单次时限和执行时间上限。阶段收束后可接续已经裁决的新子问题；不会给同一任务清零实验或修订预算。预算耗尽时，接续检查最初任务、本总控的子任务调用及登记库中的完整任务事件；只有尚未开始工作的新子问题才能进入新阶段，其他会话已领取或执行后交回的子任务也会被拦住。没有合理的新问题、出现实质复核阻断或不明运行故障时，记录原因并停止派发。

额度使用 Codex 公开的 `account/rateLimits/read` 接口。它返回实际使用比例、窗口长度、服务器重置时间和普通使用许可 `ordinaryUsageAllowed`。五小时窗口与周窗口都检查；同时耗尽时等待较晚的重置。恢复前再次读取接口，必须普通使用许可明确为true且窗口没有受限；false继续阻断，null或缺失记为未知并停止派发。不能从比例下降或已到重置时间推断恢复，也不购买额度或消耗额外的重置权益。接口不知道时间时，只做每30秒的只读复查。

额度在派发前耗尽：同轮暂停，已完成的Agent结果继续复用。额度在会话中耗尽：仅当CLI结构化错误明确表示额度限制、且账户接口证实限制时，才归档失败并等待；恢复后按原总控的剩余预算重试。失败保留，不重复已完成的实验；必要时重新独立复核。明确的额度等待从执行时间预算中扣除，原调用数、轮数和实际执行时间预算保留。其他故障不会被当成额度限制。

运行后，`data/technical/loops/<循环编号>/STATUS.html` 每30秒刷新；`checkpoints` 保存各阶段报告、任务上下文、哈希凭据和下一计划；`quota_failures` 保存执行途中耗尽的失败记录；`events.jsonl` 保存整个推进历史。页面展示最近一次额度观测时间，并非声称额度连续实时更新。

2026-10-04新增用户停止条件，2026-10-05按用户反馈收紧：**主动成果通知以实际策略账户的收益、回撤为准。**候选在相近收益下明显降低回撤，或收益超过同池小市值，且通过固定研究标准和独立双复核后，才值得停下来报告。每个设计先固定相近收益、明显改善、日期、预算与否证条件；报告年化/累计收益、回撤、年度结果和不确定性。单独RankIC提升、训练误差变化、打乱标签对照或一般机制分解，保留为阶段诊断，不触发成果通知。重大完整性或执行阻断仍可停下，明确作为故障报告，不称投资成果。新判据用政策附录保存，旧宽泛判据和旧通知不倒改。这是复核和裁决规则，不声称仅凭程序已证明策略有效。

每次成果报告末尾另起“自上次报告以来的研究路径”：按阶段简述问题、具体变化、拟合/账户新增数量、结果和接续原因，包含失败与否证分支。工程修复单列。阶段REPORT、证据与下一计划继续留存，不只展示最后一个发现。[截至本次规则修正的累计说明](ML_CYCLE_PROGRESS_20261005.html)区分循环之前的账户矩阵和循环中的新增研究。

这条条件通过新的不可改写政策附录记录，原循环配置和历史输入不改。触发后，状态变为`noteworthy_result`，报告和凭据保存在`notices`。下一子任务可以已经登记，但尚未开始计算；普通`run`和额度重置都不会解除停止。用户明确要求继续后，才用`acknowledge <循环编号> --reason "用户明确续行的依据"`确认，保留原调用、轮次、时间和失败历史。状态页给出报告路径。本地程序不能保证无人值守时自动向Codex桌面聊天发送消息；活跃会话检测到发现时会向用户报告。

通知按照具体发现的内容签名去重，引用相同旧证据的新重大问题仍会停止。确认前检查固定的收据身份、必需文件和报告正文；已失败但参与过研究的会话也纳入独立复核的隔离检查。CLI在持久停止后尝试本机Windows系统提醒，失败不会恢复研究，日志中的进程启动不等于提醒已送达。系统展示受Windows设置影响，实现采用[微软官方NotifyIcon接口](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.notifyicon.showballoontip?view=netframework-4.8.1)；这不是桌面聊天消息。

若研究者已经附好勘误证据，但在最终提交前退出，可由新的领取者完成提交后调用有限的`Campaigns.resume_review`接续原轮复核。该接口不重试研究、不能恢复失败复核者，且要求故障结束之后的新提交；原失败记录仍计入调用。原失败归档和后来的成功归档使用不同版本目录并存。

命令都从 `lhb_backtest` 运行：

```powershell
..\.venv\Scripts\python.exe tools/ml_loop.py show loop-实际编号
..\.venv\Scripts\python.exe tools/ml_loop.py stop loop-实际编号
..\.venv\Scripts\python.exe tools/ml_loop.py quota
```

需要电脑保持开机，后台进程存活，CLI登录有效。后台会话不保证出现在桌面侧栏。这是本机研究进程，不是桌面原生自动化；当前工具未提供原生定时任务入口，也没有设置开机自启。程序被强杀后会保留锁：先核查PID、子进程和日志，不盲目删锁重启。

所有历史都已经看过；不同会话与新参数不会生成未见样本。分析证据包仍明确属于事后导入，文件完整性核验、数值核验和独立复核分别记录。限定范围的验收不等于策略盈利、企业认证或未来收益保证。

接口依据：[OpenAI 官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)。本机任务的运行条件参见[官方自动化说明](https://learn.chatgpt.com/docs/automations?surface=app)。
