# 每次训练究竟学到了什么：真实模型和训练数据存档已接入

## 1. 这次做成了什么

新的训练作业现在会保存真正拟合出的模型，以及它实际使用的X、Y、样本权重和训练分数。读取保存的模型，就可以再算同一批股票的分数，检查是否精确相同，无需重新训练。此次是工程验收：短目录恢复批39项小型条件通过；恢复8次加上原失败前5次，本机累计13次合成数据拟合；没有新训练市场模型，也没有新增账户回测。

上一轮12个市场模型没有保存原始拟合对象，因此不能补造一个对象并宣称恢复了当时模型。新功能对之后的训练生效。原12模型/32账户的结论保持原样。

## 2. 用一次选股训练说明保存什么

假设以后某次训练，用2020—2022的股票记录训练模型，随后给2023之后每周的股票打分。保存的内容包括：实际参与训练的每行股票/日期、模型收到的特征数值X、实际采用的成熟收益或其他目标Y、每行权重，以及真正拟合出的预处理和模型参数。未来预测时期的收益标签不能进入训练矩阵。

X中有些原始指标可能缺失，预处理会按训练期规则处理；保存拟合管线，才能保留这种规则以及特征顺序，而不是只写一个模型名称。检查时读取原对象计算训练和后续分数，不能再次调用fit得到另一个模型。

## 3. 实际检查了哪些问题

39项条件覆盖：实际X/Y/权重与存档对应、收益或置换目标、非均匀权重、拟合对象重载、训练及后续分数精确一致、旧v1作业兼容、新v2真实登记执行、资料被篡改或调用不可信时拒绝，以及输出容量限制。审核期间禁止底层模型再次fit，零重训接受不是一句文字声明。

恢复批8次拟合由5次库级合成案例和3次原生登记案例构成；原批次另有5次已完成拟合，不能抹掉。原批39项中6项通过、33项因同一个临时路径过长而出现夹具错误，未完成验收；独立恢复第一例因漏建临时父目录在任何拟合前失败，新增拟合0；第二例创建普通父目录后在同一时钟与剩余预算内验收。仅改变项目内临时目录布局，保留两例失败和两批全部消耗，总声明预算16次、本机实际13次。3次登记案例中，两次正常完成，一次故意把模型存档容量限制得过小：模型已经拟合，保存失败。该次实际拟合仍计入总账，失败产物保留，不能退款或自动重新训练。小型登记案例使用隔离的测试研究库；主研究库此工程任务没有新登记策略实验。

## 4. 代码怎样接到已有系统

修改已有4个模块：训练执行器增加可选实际拟合信息捕获；登记协议明确v2和模型文件预算；原生worker写训练记录与拟合对象；输出审核器重载原模型核对实际数据和分数。新增learning_artifacts模块负责这些存档。原145个生产Python文件中其余141个保持字节一致，新增后共146个；4个修改文件都保留原备份。

文件校验码只用于确认资料和代码对应，不能证明策略有用，也不能证明供应商历史数据准确。模型对象及原始训练记录保留本机；读取序列化模型必须明确来自可信的本地任务。最终阶段归档是否已经完成，见总览。

## 5. 下一步怎样落到收益和回撤

现有公式执行器只支持训练区间。下一包E23H0先加入明确的后续特征执行协议，保留旧协议兼容；E23H再计算训练期已经选好的公式在后续时期的X，不能通过修改日期名称绕过时间边界。

接着E19E比较三套输入：原16个特征、增加12个表现路线公式、再增加8个探索公式；分别使用岭回归和提升树，并保留打乱Y的负对照。7次市场拟合和14条账户情景仍是未执行设计，要先冻结实际预算。最后查看含费账户年化收益、每日最大回撤、分期表现和风险敞口，与小市值、固定随机和低波等适当对照比较。工程通过没有提高任何已经核查的账户收益，也不是停止研究的理由。
