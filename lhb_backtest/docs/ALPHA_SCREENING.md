# 一千个候选怎样筛：E13 的作用和边界

假设我们已经构建了很多有意义的候选特征：龙虎榜买入集中度、连续涨停后的量价变化、流动性压力，以及它们的组合。每一个特征暂时都是“一只股票在一个决策时点的一个数字”。E13 是试验前的低成本检查和分流工具，帮助决定哪些候选值得进入模型与真实账户。它没有训练新模型，也没有新增真实账户回测。

## 把每天的工作说清楚

例如你计划在周一开盘买入、下一次周一开盘调仓。研究输入必须先列出每次决策时的股票名单、信息截止时点、买入时点和目标终点。这里的名单由外部股票池协议提供；筛选模块不会暗中选小市值，也不默认每周运行。只要传入的执行窗口一致且彼此不重叠，频率由这份计划决定。

一个候选是一个提前写好的通道：“在这份名单里，按集中度从高到低排序，选择前 K 只”。也可以提前声明另一方向：“从低到高”，或者固定条件：“只在已知连板数至少为 2 时使用”。每种方向和条件分别算一次尝试。负方向仍是买入低分股票，不是卖空。

选股规则只依赖已知 X；已经成熟的历史 Y 用于检验这份名单的结果。代码先校验标签，再计算诊断，不能将这个实现顺序说成选股前完全不读取 Y。Y 是从已声明买入时点到终点的**小数收益率**，例如 0.05 表示上涨 5%，不是未来价格。它还要带“这个结果最早什么时候能知道”的时间。尚未到这个时间的结果不能使用。保留段的未来收益数值不参与开发段筛选。

~~~mermaid
flowchart TD
    A[已登记特征与决策名单] --> B[检查股票键、信息时点、单位、缺失原因]
    P[提前保存方向、条件、家族与有限预算] --> B
    B --> C[只按当时已知 X 排序并确定股票]
    C --> D[读取已成熟的开发段收益标签]
    D --> E[覆盖、RankIC、常量、相关性诊断]
    D --> F[固定 K 名额的端点毛收益与回撤代理]
    E --> G[所有尝试保留；按家族配额分流]
    F --> G
    G --> H[性能候选与提前预留的探索候选]
    H --> I[后续：持久登记、模型、独立样本、原生账户与审计]
~~~

## 一个可以手算的例子

下面是为了检查程序而构造的四只假股票，重复三个开发窗口。它不是 A 股研究结果。

| 股票 | 特征 A | 特征 B | 组合 A×B | 窗口收益 |
|---|---:|---:|---:|---:|
| 甲 | -1 | -1 | 1 | 10% |
| 乙 | -1 | 1 | -1 | -10% |
| 丙 | 1 | -1 | -1 | -10% |
| 丁 | 1 | 1 | 1 | 10% |

A 单独排序与收益排序的关系为零，B 也为零，但 A×B 能分出两组。若只因 A 的 RankIC 为零就删除它，后面的模型或组合搜索可能无法得到 A×B。这是“不要仅凭单个特征表现删除交互材料”的反例；它不证明真实市场里某个组合有效。

设置 K=1，并列按股票代码稳定排序，组合通道选中甲，三个窗口的端点毛收益为 1.1³−1=33.1%。A 通道选中丙，毛收益为 0.9³−1=−27.1%，端点最大回撤为 27.1%。这些数字由人工设定的收益生成，只用于核对计算。

如果 K=5 而名单只有四只，每只占 1/5，第五个名额保留现金，现金比例为 20%。四只的收益正负抵消，组合窗口收益为零。这个代理采用**固定 K 个等权名额**；原生账户若采用“实际选中几只就全部等权买满”，权重口径不同，比较之前必须明确对齐。

假如甲已经被选中，但它的目标收益缺失，本模块不会改选乙，也不会把甲的权重分给其他股票。整个窗口收益标为未知，后续累计路径也未知。因此它不会靠删除缺失结果获得一条更好看的收益线。

## 筛选依据是什么

覆盖率说明符合条件的股票里，有多少真正有这个特征；条件未知与条件不成立分开记录。一个缺少龙虎榜覆盖的股票，不能因此被当成“确定没有上榜”。

RankIC 用于诊断排序关系。配对不足或分数/收益全为常量时，输出不可计算及原因，而不是填零。冗余检查记录部分特征对的排序相关性；高相关不会自动删除特征，它们仍可能在条件、交互或模型里有不同作用。

性能候选必须有同一组完整窗口，先满足数据质量要求，再在各自家族里保留收益更高、回撤更低的 Pareto 候选并受名额限制。如果另一候选收益不低且回撤不大，并且至少一项严格更好，前者被它支配。名额不足时按毛收益优先、再回撤、最后通道 ID 确定顺序。这是一种提前声明的分流规则；最好的相对候选仍可能亏损。

探索候选需要**结果出来之前**就声明理由，例如交互材料、稀有事件、另一类经济机制，并预留家族名额。达到基本质量要求后可以进入下一步，即使边际 RankIC 低或收益窗口还不完整。进入探索通道只表示值得验证，不能表述为赚钱或已经证明有效。代码按通道 ID 分配有限探索名额，不偷偷根据结果改理由。

## 收益代理能告诉我们什么

本模块连乘各个非重叠窗口的端点毛收益，计算端点净值与端点回撤，用于快速发现明显无效、异常或值得进一步检查的候选。它没有订单、持仓延续、成交限制、公司行动现金流、费用或窗口内每日净值，因此：

- 不输出年化收益率，不声称真实账户最大回撤。
- 端点看起来平稳，窗口中仍可能发生很深的回撤。
- 每个窗口按固定名额重新评价，不表示实际交易笔数或换手。
- 成熟 Y 与代码身份声明不等于供应商历史已经认证。

用户所要求的最终判断仍来自核查过的原生账户收益与回撤，并与相同股票池的小市值、固定随机种子对照比较。固定随机 11 中的 11 是随机种子，不是只持有 11 只。

## 调用者会得到什么

| 输出 | 用人话说 |
|---|---|
| daily | 每个通道、每个日期：多少股票可用，条件真/假/未知，排序关系能否计算 |
| selections | 只按已知 X 确定的股票、分数、名次与固定名额权重 |
| windows | 每个窗口的毛收益、现金比例、未知状态、累计端点净值与回撤 |
| trials | 全部通道，包括负结果；是否进入下一步以及具体原因 |
| redundancy | 有限预算内检查了哪些特征对，还有多少对未检查 |
| receipt | 协议、实际消耗的开发输入摘要、实现版本、环境、尝试次数及能力边界 |

入口是 src/alpharesearch/screening.py 的 ScreenSpec.from_dict、screen 和 ScreenRunner。完整可运行的合成输入见 tests/test_alpha_screening.py 的 example。screen 是单次纯函数调用；ScreenRunner 限制一个进程内的调用次数和候选×方向×条件次数，失败尝试消耗预算，不能退款重新试。账本在运行前保存完整协议和每个通道的方向、条件、家族、假设；通道意图预算拒绝与已消费预算的输入失败分开记录。超出调用次数上限的请求在准入之前直接拒绝，不消耗预算、不计算，也不进入这个有限账本；跨进程完整注册仍待 E13B。没有选中股票或关闭冗余检查时，空表仍保留列名。数值累计若溢出，输出未知及明确原因，不能留下无穷大收益。

这一步只有纯 API 和本地验证记录，**尚未接入跨进程持久登记、冻结执行与崩溃恢复**。本地计划保存在运行之前，但不能叫 ResearchOps 已登记的筛选 experiment。E13B 将补持久筛选，持久学习也需补齐，之后才能开展真正的大规模特征、模型和账户研究。任何人若手动反复调用纯函数，仍能绕开进程内总额；本阶段不声称解决了这个问题。

## 为什么这样设计，接下来做什么

[Brown 等人的特征选择论文](https://jmlr.org/papers/volume13/brown12a/brown12a.pdf)讨论了边际筛选与条件依赖的区别；[Factorization Machines 的交互研究](https://www.jmlr.org/papers/volume22/20-1170/20-1170.pdf)提供了低秩交互建模方向。它们支持保留交互假设，不直接证明 A 股盈利。[scikit-learn 的置换重要性说明](https://scikit-learn.org/stable/modules/permutation_importance.html)提醒重要性依赖模型与相关变量。[回测过拟合论文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)则提示搜索与选择本身也会产生偏差；完整尝试账本不能自动变成任意数量的独立统计试验。

接下来先测 32/64 列与一至两个进程的实际容量，再补持久执行，继而比较龙虎榜、集中度、板型、财务、交互与不同模型的真实账户。每日历史还可以组织成序列输入，不必为了尝试序列模型先购买分钟数据。广度清单保留在项目纲领与研究雷达中，不能把筛选规则或现有模型当成永久范围。

源头单位检查在数值转换前识别原生、object 和 categorical 容器内的实际布尔值：binary 特征可使用它们，价格等非 binary 特征必须拒绝。普通数值列走直接数值路径；这里核查仍保留在 FeatureBlock 中的类型，不能倒推上游已转换的供应商数据。

同一源头边界也在转为 float 前拒绝复数：不能靠丢掉虚部把错误数据变成合格金融特征。原生、object、categorical 三种容器都覆盖；时间对象在已验证的官方组装路径拒绝，未新增将时间单位隐式当价格的接口。
