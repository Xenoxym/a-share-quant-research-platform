# 训练一次，保存预测，之后怎样接着做回测

E16D接口说明，2026-10-07。当前验收状态以任务库和阶段收据为准。

**本阶段把已有训练程序接到正式任务链。它不改变学习目标，也不强制先选小市值；主要让输入、模型、已用拟合名额、失败和预测在退出程序后仍能接续。**

## 先用一个例子说清楚

输入表每行是一只股票在一个决策时刻的X。例如“最近的涨跌、量的异常、当时已知的事件特征”，可以有不同过去窗口；每个字段由特征定义和可用时钟说明。不是硬规定16项乘5天。LearningSpec声明具体列、股票范围和训练/预测日期。

假设用1月2日至4日训练，在1月7日截止，给1月8日至9日的股票打分。1月4日的一个持有窗口要到1月10日才结束，那部分Y不能用于这次训练。1月8、9日的未来收益完全不用于选择预测名单，甚至可以不提供；程序仍按当时的X为声明的全部股票输出分数。

Y是每行声明的实际执行起点到目标终点的收益率，例如下次调仓开盘卖出时的收益。它不固定等于第五天价格，也不必是周一开盘到周五收盘。后续组合和账户必须采用与决策表一致的执行约定。

```mermaid
flowchart LR
 A[声明X Y窗口及模型] --> B[登记拟合名额与输入SHA]
 B --> C[冻结源码和环境版本记录]
 C --> D[只训练一次并保存预测]
 D --> E[恢复核查原文件 不再fit]
 E --> F[按分数形成组合]
 F --> G[原生账户收益与回撤]
```

当前支持六个已存在的表格模型：ridge、elastic_net、huber、random_forest、extra_trees、hist_gbdt。未来可以扩展序列、图、表示学习或直接组合目标，这六类不是长期蓝图的上限。

## 一次登记具体保存什么

沿用七个输入角色：registry、assembly_values、assembly_missing、assembly_definition、assembly_receipt、decisions、labels。每个输入有项目内相对路径、SHA256和字节数；引用证明文件和声明一致，不证明上游算法曾执行或供应商历史正确。

`kind=alpha_learn`的spec严格包含schema、learning、model、budget。learning是完整causal-learning-v1，model是完整tabular-model-v1；budget声明max_input_bytes和max_task_fit_intents。调用沿用Research.register/execute/recover及tools/research.py。完整可运行合成构造见tests/test_alpha_learn_registration.py，不能把此段字段说明当作完整提案。

第一次登记固定本任务的拟合意图总额。每个不同正式作业计一个意图；失败、取消、冻结失败和重启都不能退回或清零。同一实质定义的重复登记返回原作业。不同作业即使训练数据相同也重新计一个意图；当前不宣称有跨作业已拟合模型缓存。

## 哪些文件给后面使用

| 文件 | 用途 |
| --- | --- |
| predictions.parquet | 每只股票的分数、决策与执行时钟、fit_id与prediction_id；后续组合输入 |
| learning_receipt.json | 成熟训练标签、预测成员、实际消费的数据指纹、一次fit记录；保留纯API自己的能力声明 |
| model_metadata.json | 具体参数、特征顺序、训练中位数、缩放参数和环境版本；不是完整可重新加载的估计器 |
| attempts.json | 登记意图及成功或失败的过程账本 |
| manifest.json | 把上述文件、输入和冻结源码绑定到这次任务 |

训练只在训练行上拟合缺失填充、缺失标记和必要缩放；测试或预测行不会重新计算这些参数。外层收据说明持久执行，原纯学习收据仍如实写进程内能力，不改写旧API的历史声明。

## 核查能证明到哪一步

收取、恢复、提交和复核只重做冻结的因果数据准备，核对成熟标签身份、预测股票及时间、有限浮点分数、训练变换元数据和全部文件身份；不会再调用fit，不加载任意外来模型序列化文件。手工ridge例子另外验证一个已知闭式结果。

**这不是独立重新训练六种模型来重现每个分数。** 初次收取之前，如果有人把一个有限分数和所有相关指纹一起一致替换，结构核查不能单独证明其数学真实性。这是明确保留的边界；正式收取后，任务库额外绑定原输出和审计身份，之后改变文件会被拒绝。不能把verified字段解释成所有模型算法的独立数值认证。

共享worker槽、Windows握手、采样RSS、线程与超时监督沿用既有流程。父进程的同步核查仍没有单独资源槽和RSS/超时限制；本阶段只执行事前限定的小批，不能声称全链硬隔离。输出预估是保守拒绝，实际文件和最终清单也会检查；不是OS磁盘配额。

## 怎么走到真正的收益结论

持久预测可以直接接已有组合绑定和原生账户核查。之后在统一股票池和执行口径下比较价格量、板型/连板、龙虎榜/集中度、财务/市场、机制交互以及不同模型，保留小市值、固定组合和费用反事实对照。需要看到核查后的更高收益或相近收益下更小回撤，才达到用户要求的重要成果标准。
