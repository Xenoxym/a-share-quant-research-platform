研究阶段记录模板

依据：长期纲领。本文件是人工阶段记录模板，不是 tools/research.py submit 的 JSON 字段规范；提交仍使用工具规定的四个字段。

阶段身份与范围

  • 日期、任务 ID、父任务、角色与当前租约；阶段开始和结束时间。
  • 问题、假设、预期、否证条件和适当对照。
  • 长期地图的位置；本阶段明确范围、依赖和预算。
  • 数据快照、可用日期、代码身份、运行/证据 ID；区分设计、事前登记与事后分析。

为什么做这一阶段

  • 沿已有证据深化的候选方向。
  • 至少一个不同机制、表示或决策层的竞争方向。
  • 选择理由、成本及最便宜的否证试验。
  • 如果是新研究主题：近期清单之外的检索、来源和阅读深度；若无合格新线索，记录搜索与拒绝理由。
  • 若为包内实施/紧急修复，说明为什么本阶段不做新主题检索。

全部工作与尝试

尝试/产物 登记或证据 ID 实际状态 资源消耗 得到什么/为何失败
待填写 待填写 设计/运行/失败/完成 fit、账户路径、时间、调用分别计数 待填写

非法候选、重复、取消、工程失败及负结果都保留。不要只列晋级者。

结果与解释

  • 工程阶段：实际检查、通过项、未通过项和受影响结论。
  • 预测阶段：诊断指标、分期/子样本稳定性；明确尚无账户结论。
  • 账户阶段：收益、回撤、曲线、分期、敞口、对照、费用反事实和未解决权益；完整数值链接。
  • 当前证据支持什么、不能支持什么；有哪些竞争解释？
  • 历史被查看或反复使用的程度；选择偏差、数据依赖与统计不确定性。

对知识地图的更新

  • 新知道了什么；改变了什么既有假设？
  • 雷达条目新增/状态变化；关联来源与实验 ID。
  • 尚未研究、缺数据、工程受阻和有限范围否证分别记录。
  • 如达到覆盖审查时点：近期投入是否过于集中？下一轮如何处理未覆盖方向？

下一阶段与停止原因

  • 下一阶段候选、选择理由、依赖、预算及验收/停止条件。
  • 可复用产物、不可变历史路径、领取及交接要求。
  • 本轮停止原因：阶段完成/值得通知的账户成果/额度/用户要求/失败待处理/其他；不确定则写明。
  • checkpoint 或 handoff 的位置与时间。

向用户宣布值得注意的成果时，放在报告末尾

“自上次汇报起：依次做了 A、B、C；其中哪些失败、哪些只是中间诊断、哪些进入了账户核查。此次值得注意的结果相对什么对照改善了多少，局限是什么，下一步如何检验。”
