排名实验停在训练前：发生了什么，怎样接续

本阶段准备了真实训练输入，但没有训练出模型，也没有运行回测。 不能据此说排名目标有效或无效。六个成熟Qlib公式接入已完成51项测试和双结果验收；这与排名模型的收益验证是两件事。

1. 原来想检验什么

X保持原36项：最初16个价量特征，加20个既有筛选公式。模型仍为32棵浅随机森林，深度5、叶节点至少500条、随机种子11、两个数值线程；仅修改训练Y。

原始目标直接学下一持有区间收益；中心化目标减去同日股票均值；本次日期内排名把同日收益顺序缩放到−0.5至+0.5。例如三只股票后来收益−8%、+2%、+9%，排名目标分别为−0.5、0、+0.5。它用普通随机森林回归学习这些数，仍不是专用成对或列表排序损失，也不直接优化账户年化收益。

训练是2020–2022已成熟379842条记录，计划预测2023–2026年9月550711条记录。计划仍周调仓、共同合格主板名单内选分数前100只、目标资金比例98%。原始标签是调仓开盘至下一次调仓开盘的收益，不是统一周一至周五收盘，也没有使用持有路径的最高价。训练外历史已被查看，不能称真正未见验证集。

最终应看同账户下含费年化收益、每日最大回撤及分期表现；RankIC只是诊断，不能替代收益。

2. 实际做到哪里

两名复核者接受SOURCE03后，实际启动检查通过：2026-10-11 03:05:23 UTC，物理可用约13.88GiB，可承诺余量约6.87GiB。任务真实领取；登记准备过程中实际构建训练输入，确认379842成熟训练行和550711预测行，冻结了输入与代码。

随后，执行子进程在调用真正训练执行器前再次检查资源，检查断言失败。因此没有产生原生训练launch、worker_started、训练receipt、model.joblib、training_trace或预测输出。只有准备好的登记文件，不是训练完成。

登记中的fit_id是根据拟使用的数据、目标和实现生成的身份，即使有这个编号，也不代表已fit出模型。模型文件、实际调用记录和核查通过才是训练证据；本次都不存在。

失败后仅做终态收取，取消尚未启动的登记。新增注册fit意图1次仍保留并计数；实际fit、预测和账户均0。所有自有进程最终0、无监督错误、无待释放资源。学习失败标记使后续账户入口拒绝继续；没有自动重试或伪造通过。

失败检查没有保存该瞬间的具体容量，因此不能只凭附近采样宣布究竟哪个字段、差多少字节。这是需要修正的诊断缺口。物理和commit都是启动条件，磁盘剩余空间不能代替commit。

当前commit余量仅在原6.5GiB门槛附近波动。后续应在父入口至少留约8GiB可承诺余量，保留真正执行入口原6.5GiB及12GiB物理门槛，并把每次检查的实际值和失败原因写出。建议再释放约2–3GiB内存取得余量；这是资源建议，不是精确训练峰值保证，也不授权改系统分页文件或结束其他应用。

完整68特征不能套用本次门槛。R24P只验证26项小准备等价，全68候选尚未实际验证容量；后续需独立SOURCE、一次prepare且0fit/账户、真实峰值和与原输入身份的比较。

4. 已完成与接下来

成熟Qlib六公式接口已经接现有FeatureBlock、特征登记及决策组装；51项实际测试经双结果复核接受。它只覆盖Windows/CPython3.12、12股120日的小集成，不证明Linux后端、全市场、复权正确或新Alpha收益，也未自动给当前模型新增六列。

排名学习的收益问题仍未回答；原始、中心化和小市值等旧账户没有重跑。下一有限任务先补资源检查日志和启动余量，资源确实改善后只运行原未执行排名1模型/零费及含费2路径。完整68容量、直接市值/龙虎榜/板型/财务输入、成熟滚动、序列关系、有限公式搜索和组合学习继续保留；不能持续用接口测试代替经济结果。

本批代码与新报告由PUB11统一公开并核对新提交CI，不能借用旧3114548的CI覆盖新代码。原始数据、模型、安装环境、登记和复核会话凭据保留本机。
