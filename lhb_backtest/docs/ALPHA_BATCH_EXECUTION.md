# 四个公式怎样真正开始计算：E12 有限批次执行

现在可以把登记的 Alpha 公式交给数值进程计算。输出是每只股票、每个开发日的公式值和缺失原因。这个步骤没有训练模型，也没有买卖股票；之后的 E13 筛选、E16 学习、E17 选股与 E18 账户核查负责把它接到收益和回撤。

## 一次运行发生什么

例如登记四个公式，引用已保存的价格、量、事件等来源块。在运行之前，系统已经保存了四个公式、完整股票名单、日期、决策时刻、来源文件哈希、代码和预算。运行时按下列顺序进行：

1. 再核对冻结清单和实际输入。环境版本改变或旧登记没有执行器，就拒绝启动，需要新登记，原记录保留。
2. 预留共享研究库中的一个数值槽位，并检查可用内存。最多两个公式计算进程；资源不足时实验仍是“计划中”。
3. 从登记目录的代码启动解释器。之后修改工作区源码，改变不了这一次正在运行的代码。
4. 准备热身和开发段，逐个计算白名单表达式。输出只保留开发日期；保留段不参与公式计算或选择。完整来源文件会为身份校验而被读取，因此不能说“从未读取包含后期记录的文件”。
5. 记录每个候选完成或失败，原子保存文件。相同公式的不同登记名称仍占名额；失败和取消不退款。任一候选失败，整批保持失败并保留部分产物；只有全部候选完成才可成功收取。部分失败批次目前不自动晋级，之后若救回完整子集须另立明确登记，不能隐藏原失败。
6. 等解释器退出，再独立核对全部输出文件、开发段所有股票键、时点、数值与缺失的一致性、依赖与冻结实现身份。通过后才在任务库标记完成。

~~~mermaid
flowchart LR
  R["登记：公式、数据、日期、预算"] --> F["冻结代码与输入身份"]
  F --> S["预留最多两个数值槽位"]
  S --> W["受监督的冻结解释器"]
  W --> A["全部候选：值、缺失、失败原因"]
  A --> V["独立文件、名单、时点、来源身份核查"]
  V --> D["完成的特征证据"]
  W --> X["失败或取消：保留名额、日志、部分产物"]
  D --> N["后续筛选 → 学习 → 持仓 → 账户收益/回撤"]
~~~

## 一个能手算的例子

小夹具中，两只股票在1月3日、4日的收盘价都是10.5，参考前收价都是10。

公式是 cs_rank(close / pre_close)。两只股票的比值同为1.05；并列排序取平均名次1.5，再除以股票数2，每个股票的得分都是0.75。两个开发日应该留下四行，不能只留下第一只股票，也不能偷偷删掉缺失行。

这里的0.75只是特征值，不是75%收益或模型置信度。收益与回撤需要之后的完整账户路径。

## 怎么用现有接口

从项目的 lhb_backtest 目录执行已有工具。proposal.json 使用[批次登记合同](ALPHA_BATCH_REGISTRATION.md)的 kind=alpha_batch，另可给出下列 resources 设置；省略时采用同样的有限默认值：

~~~json
{
  "schema": "alpha-worker-resources-v1",
  "slots_per_research_root": 2,
  "library_threads": 2,
  "max_process_rss_bytes": 2147483648,
  "min_available_memory_bytes": 1073741824,
  "max_output_bytes": 1073741824,
  "memory_policy": "sampled_soft_stop",
  "output_scope": "development_only"
}
~~~

~~~powershell
..\.venv\Scripts\python.exe tools/research.py register --session <session.json> --file <proposal.json>
..\.venv\Scripts\python.exe tools/research.py run <experiment-id> --session <session.json>
..\.venv\Scripts\python.exe tools/research.py recover <experiment-id>
..\.venv\Scripts\python.exe tools/research.py cancel <experiment-id> --session <session.json> --reason "停止依据"
~~~

完整批次执行需要 research 可选依赖。本机已有 psutil，未为这一步额外安装或购买服务；公开依赖清单包含它。

## 资源与中断怎样处理

预留量用于决定能不能同时开始两个作业。运行中每0.2秒采样实际启动进程的 RSS 和系统可用内存，超过已登记内存、时限或收到取消请求就停止本次进程。数值库线程环境限制为1或2；Arrow 的数值池同样限制，I/O池为1。监测线程、解释器启动器和隐藏控制台属于辅助开销，也计入父监督的内存观察。

Windows虚拟环境有启动器、实际解释器和可能的隐藏控制台辅助进程。它们通过父子关系、可执行文件、参数、PID及创建时间验证；只允许一个实际数值解释器。恢复时先与独立资源预留核对完整启动身份，再确认所有登记进程都已退出，最后提交终态与释放资源。Linux直接解释器没有这层启动器；相应分支仍需公开CI验证。

这是采样软限制，可能短暂超出上限，不能称为操作系统硬内存沙箱。槽位只覆盖同一研究库的 Alpha 作业，不限制其他程序，也尚未统一约束旧 ML/账户执行器。公式仍是受约束AST，本步骤不是外部自由代码沙箱。

父监督进程失去后，已启动 worker 在完成导入和作业核查后还有自监测线程，采样检查时限、内存和取消；写失败收据遇到磁盘/权限错误，也必须退出，不能让记录失败使监测失效。父进程不在的启动阶段与观测缺口不能冒充完整监测；恢复记录会如实标记无法提供峰值RSS。未知的启动身份、无收据退出或未绑定的预留仍需检查，系统不会猜测并重复启动。更完整的故障演练接续 E29。

计划中取消的原有终态是 cancelled。运行中取消是请求，由监督或worker消费；本次实验保留为 failed，错误明确写“Cancellation requested”。如果计算已在消费请求前正常完成，则以真实完成结果为准，不声称取消请求即时生效。

父监督真实计算/资源异常时，在与收取器共用的作业锁内先单独保存 supervision_failure.json。它绑定冻结输入、实验和当时的启动记录，保留原始失败原因；已有 worker 成功或失败收据不覆盖。再提交数据库失败状态、补写资源观察及必要的失败收据。数据库暂时不可写则保留独立资源预留；恢复必须先核验确切进程全部退出及预留身份，然后优先收取父监督失败，即使 worker 已留下成功收据，或没有收据，也不能据此将原失败改成成功。首次合法观察仍保持不变。

收取事务和计算失败分开：原监督失败、worker 失败或已通过审计的成功，都先确定结论，再只提交一次数据库。收取前状态读取、锁内状态刷新、锁忙后的状态读取和终态提交失败均返回专用 CollectionCommitPending；公开 recover 保留 running、原失败原因和身份预留，完整 execute 返回“等待再次收取”，不能把数据库错误重新提交为计算失败。下一次只调用 recover，不重新计算。输出审计的真实错误仍保存为独立失败记录，即使第一次失败状态提交不可用，也不会丢掉原因。

终态数据库提交是结论的边界：另一收取器若在监督失败记录保存之前已经提交终态，后来的异常记录不能改写原结论；重复 recover 只重试确切身份的资源清理。失败记录和数据库同时无法写入时不能保证保存新事实，系统保留预留及可保留的材料、记录缺口，不声称自动恢复保证或自动重跑。未知启动、无法核验的失败身份仍需人工检查。

## 输出能证明多少

独立输出核查会拒绝漏股票、混入保留段、错误时钟、未登记文件、伪造来源/实现身份、错误计数以及值与缺失原因不一致。完成结果保存清单、审计、收据、启动和资源观察的哈希；提交任务与复核时再次验证。

终态收取与父进程观测写入使用同一作业的永久内核锁。并发收取不会互相覆盖文件；先保存的合法观测保留，若先保存了恢复时的观测缺口，迟到的完整父观测也不会覆盖它，避免已提交哈希失效。锁等待有时限。父执行入口遇到收取锁忙，会保留原状态、终态收据及完整资源预留，并返回待收取备注；它不把锁忙当成计算失败，也不退款。稍后用 recover 收取同一个已退出作业，不重新 execute。这个待收取分支仅用于已验证退出后的观测/收取；启动时的锁忙沿启动失败路径记录，不能冒充有完整身份的待收取。已完成或失败的作业也会由公开 recover 重试身份安全的槽位清理，原终态、收据与输出不重写。

核查不重新计算全部公式数学，也不认证供应商历史或证明策略赚钱。结果不会将“文件身份核查”写成“独立数值全量重现”。学习、组合和账户分别采用已有专门核查，最后的晋级仍看收益与回撤。

## 代码入口与接续

| 文件 | 负责的事 |
|---|---|
| src/researchops/alpha_experiments.py | 登记与冻结身份，分派运行/核查 |
| src/researchops/resources.py | 内核锁、有限预留、进程身份与安全释放 |
| src/researchops/alpha_execution.py | 启动、父监督、取消请求、收取与恢复 |
| src/researchops/alpha_worker.py | 冻结公式数值计算、子自监测、候选输出与收据 |
| src/researchops/alpha_output_audit.py | 独立输出名单、时点与身份核查 |

资源接口依据 [psutil官方进程与内存说明](https://psutil.readthedocs.io/stable/)，短预留锁采用 Python 官方的 [Windows文件锁](https://docs.python.org/3/library/msvcrt.html) / [Unix flock](https://docs.python.org/3/library/fcntl.html)。[Joblib官方示例](https://joblib.readthedocs.io/en/stable/auto_examples/parallel_memmap.html)说明共享大数组可减少传递成本，但并行开销也可能超过计算本身。因此这里不默认加磁盘缓存、也不承诺并行加速；E10已有“热缓存反而慢”的项目证据，E14将测32/64列的用时、内存、磁盘和输出一致性。

下一步 E13 留下诊断与晋级总账，并保留稀有事件/条件交互通道；E14测实际容量，再进入 E19 新特征与模型的真实账户对照。候选数量增加和诊断变好，都不单独触发“值得暂停告诉你”的策略成果条件。
