训练结束以后，怎样计算未来每只股票的输入

1. 用星期五的一次选股说明

假设模型用2020—2022年训练，到2023年的某个星期五收盘后，需要给每只当时合格股票打分。先读取当时已知的原料，再计算训练阶段已经固定的公式；这些新日期的公式数值就是未来预测用的X。股票未来涨跌Y不能参与这个步骤，也不能因为后来缺少Y就把股票删掉。

旧执行协议只能计算训练区间。此次为原生公式作业增加明确的后续区间和固定名单来源，保留旧v1/v2兼容。51项合成条件通过，4个隔离登记作业实际计算8个小型公式；没有计算真实市场的20项后续公式，没有训练模型或增加账户收益。

2. 名单固定，数值随当时数据变化

表达式、方向和候选身份来自已核查的训练名单；后续每个日期输入新原料，计算新数值。比如训练名单保留了价格变化与交易状态的交互，到了新的星期五只代入那时已知的价格和状态。固定名单不是把旧分数复制到未来。

新协议要求收据核对候选全集、完整晋级名单、表达式、训练截止和来源身份。本次实际测试用3项合成库、晋级2项；真实256项库和20项名单的绑定与执行属于后续E23H。名单现在以回溯方式生成，不能宣称在2023年真实事前产生。所有历史已被研究者查看，后续区间也不是未见盲测。

3. 为什么还会计算一些更早的原料

若公式需要延迟或滚动窗口，新区间第一天也需要更早的已知数据作为预热。这些原料可以被实际计算，但输出只包含声明的后续共同名单。不能把“没有训练期输出”写成“完全没有读取或计算较早数据”。合成延迟案例专门检查了这种区别。

计划行数与实际执行行数分开；输出保留真实股票/日期键、缺失原因和已知时间。有效0分与未知NaN不同。原料缺失不能填成0，也不能把下一个日期的原料补回较早日期。

4. 此次实际验收的范围

51项条件检查协议、固定名单绑定、时间区间、预热、未来标签角色拒绝、输出键/缺失/时钟篡改、登记与执行，以及旧版本兼容。4个隔离原生案例分别为v1、v2、v3和v3带延迟；每个计算2个公式，共8次实际合成表达式尝试，零额外审核重算。

生产代码修改4个已有模块并新增batch_partition，共146→147个Python源码文件，原142个未涉及模块保持；修改前备份、历史目录和数据库实验行保全。工程验收不是公式有收益的证据。阶段最终归档状态以总览为准。

5. 接下来怎样得到收益答案

E23H用已经固定的20项候选，真正计算2023—2026后续决策日期的X；只计算特征，不读取后续Y挑公式。之后E19E比较原16、扩展28和36个输入的有限模型与含费/零费账户；E23I直接公式选股是单独路线，需另声明排名平分、资格和仓位规则。

本轮路径：八类训练筛选→原G归档超时保留→独立恢复核查→E21C实际模型与训练数据存档→本次后续特征协议。真实后续公式、组合模型及账户仍待运行；随机表示、序列、关系、自动搜索和风险配置继续保留。
