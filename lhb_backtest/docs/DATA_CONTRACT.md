# 数据获取与研究使用约定

## 2026-09-25 全项目审查补充

- 备选 AKShare/BaoStock/Tushare 日线使用不复权价格，成交量为股、成交额为元。实时获取写入 `quote_contract=raw-shares-cny-v1`；既有文件口径不明或来源不同时，要求独立输出路径，不直接混写。备选行情不自动具备主路线的历史证券池、状态、限价和基准覆盖。
- 获取任一股票失败或汇总缺请求交易日，不得报告成功。汇总部分响应保留为 `.partial.parquet`，正式汇总保持原样；恢复空响应继续待处理。日线按同源已知口径合并，保留请求区间之外的历史。
- 标签以市场交易日期寻址；`max_continue_board_days` 在观察窗口内尚未确定的连板留空，`observed_continue_board_days` 保存已观察下界，`continue_board_censored` 标记遇到未知。到达最大研究期限的已知连板长度仍是该期限内长度，不表示已经终止。
- 网格的 `ranking_sample_count` 是排序目标实际有效标签数；`ranking_eligible` 标明是否满足门槛，低于门槛的组合不称为最佳。
- 完整修复及实际验证见 全项目审查报告（本机证据，未随公开源码提供）。

## 菜单 2 实际做什么

先检查已发布 Parquet 是否覆盖请求的已完成交易日并通过质量检查。若已覆盖，直接复用。否则调用本地修复后的 SimTradeData README Option 2 入口 `scripts/download.py --skip-mootdx-ohlcv`，并设置 `SIMTRADE_DAILY_MARKET=1`：BaoStock 原生日频查询同时保存缺失日期的行情、估值和历史状态，Mootdx 负责除权与财务。日常流程不传 `--tdx-download` 或 `--tdx-source`，不下载、读取或重新导入 hsjday.zip。

随后调用 SimTradeData 原生导出器，复用未变化的股票文件，校验后发布；再更新项目日线、龙虎榜汇总和席位明细。只有这些步骤全部通过才显示更新成功。菜单 3 是席位的单独续传入口。菜单 4 重建研究表，并执行跨表数据契约验收。

这里使用的是经过本地修复的 SimTradeData 下载和导出代码，不能描述成“完全未修改的上游版本”。源码差异与部署哈希保存在 `research/menu2_update_20260924/`。

## 必须遵守的时间与字段含义

- 历史 ST 必须来自当日日频 `isST`，停牌来自当日 `tradestatus`。股票池返回的名称和龙虎榜简称可能是当前名称，只能展示，不能推断历史状态。
- `.source_state.json` 记录历史状态核对范围；范围外状态不得自动视为非 ST。
- 财务字段关联日估值时，财报期末日期及公告日期必须都不晚于该估值日期。来源不提供完整的历次财报修订版本，因此不能将这项检查扩大解释为“已恢复所有历史时点的原始财报版本”。
- SimTradeData 的 high_limit / low_limit 是上游按规则生成的字段，不是逐笔取得的交易所原始限价。项目保留来源值，并只在已支持、已核对的普通交易制度下使用；特殊制度、来源规则不符或价格越界时保持未知，禁止用百分比近似代替可成交性判断。
- 一只股票同日可能有不同披露窗口。汇总及席位选择同一个完整报告；其他报告保留在来源文件。窗口包含 1 / 3 / 10 / 30 日及无法确定的异常期间，不能统统当作单日交易金额。
- 融资买入、融券卖出监控披露可以合法地只有一个方向，必须标记 `disclosure_kind`，不能伪造另一侧。普通榜单缺一侧仍是缺失。
- 同一页中相同名称、金额的“机构专用”席位可能是不同匿名机构，不能简单去重。买卖两榜的合并金额核对也不能把重复上榜的同一席位计算两次。
- “自然人、中小投资者、机构”等投资者分类披露标记为 `investor_category`，保留来源记录，但不生成营业部席位金额、集中度或机构席位计数；分类可能相互包含，禁止简单加总。明细接口独有而汇总接口不存在的事件在覆盖报告 `source_only_events` 中列出，不伪造其汇总数据。
- 提供方的后续收益和“成功率解读”只留在原始数据，禁止作为事件预测特征。当前简称推导的旧涨停百分比阈值也不进入特征表。
- 当日收盘到后续收盘的收益是研究标签，包含次日开盘前的跳空；不能直接冒充次日开盘买入的可实现收益。末尾事件尚未发生的未来收益应为空。

## 验收与失败

菜单 2 报告在 `data/update_reports/menu2_latest.json`；正式数据发布报告在 `latest.json`；重建后的跨表验收在 `project_quality_latest.json`。单纯文件可读、最大日期够新、记录数较多，不构成完整验收。

采集失败、分页数量不符、事件缺口或已知字段异常不能被报告为成功。验证失败时保留已发布数据以及可恢复的采集进度，不用部分新数据覆盖正式数据。
