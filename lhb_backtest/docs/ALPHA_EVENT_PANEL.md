# E03：给每只股票关联当时已经知道的龙虎榜信息

本包新增 `src/alpharesearch/panel.py`。它负责把 E02 的全部原报告接到任意明确提供的日期×股票名单；不选择小市值，不把名单缩成上榜股票，也不决定买卖。旧模型和账户还没有自动改用本模块。

## 周五与周一的例子

某股票周五有龙虎榜报告，但目前只有交易日期，按 E02 保守代理规则，周六上海午夜以后才可用。

- 周五 15:10 做决定：这份报告不进入输入；不能用“后来发现当日上榜了”来制造一个特别的缺失标志。
- 周一 15:10 做决定：可以关联这份已知报告，年龄为 1 个市场交易日。
- 同一股票周五还有三日窗口报告：也单独关联，保留自己的 ID 和窗口，不把重叠金额加起来。
- 另外没有取得报告的股票继续留在名单。没有足够覆盖证据时，其事件数量是缺失，不是确认的 0。

关联先要求 `known_at <= decision_at`，再限制观察日期窗口；所有钟点统一成 UTC 纳秒，上海交易日期用于日历。纳秒、微秒、毫秒混用不会改变比较结果。

## X 是什么，池子由谁决定

输入名单必须给 `trade_date`、`stock_code`、带时区的 `decision_at`，并声明 `universe_id`。该名单可以是全部历史可用股票，也可以是某项事先约定的资格名单。**本适配器没有市值筛选，也没有龙虎榜筛选。** 当前每日每股只允许一行；多次盘中决策属于后续更细频率合同。

输出仍有每一行名单。新增的轻量信息是“已观察到的报告数量”、最近已知事件的市场交易日年龄，以及覆盖、历史不足和版本限制。报告数量没有完整覆盖时只是已取得的下界，不是全部事件次数。量价 X、财务 X、Y、模型和目标权重在后续模块分别接入；调用方额外传入的标签等列不会自动复制成 X。

这里 `window_sessions=20` 明确指当日及之前 19 个市场交易日的观察日期；即使日期落在窗口里，尚未公布的报告仍不能用。它不是规定持有 20 天，也不改变 Y 的期限或周调仓规则。

## 三种特别容易混淆的情况

| 情况 | 事件数量 | 状态 |
|---|---|---|
| 取得了已可知报告 | 记录中观察到的数量，可能是下界 | `present` |
| 全报告范围和公布边界有足够、明确的覆盖证明，确实没有取得事件 | 0；事件年龄仍没有定义 | `verified_no_event` |
| 没找到报告，但源覆盖不能证明完整 | 缺失 | `source_uncovered` |

历史日历不足时单独标记 `insufficient_history`。一个窗口尚无任何按规则可以公布的日期时标记 `not_yet_known`；这个状态来自日历和公布规则，不能来自未来报告的存在。

`CoverageProof` 必须声明所有原报告、日期、市场、不可变证据 ID、版本及完整日期公布规则。已覆盖“所有已知上榜股票”的旧收据不能升格成“所有未上榜股票也已确认”的证明。合同检查声明的形状及其与已知报告时点是否矛盾，**不替操作者证明外部证据真实或已复核**。实际生产接入还需证据登记与独立来源核对。

本次真实调用没有提供该证明，所以没有伪造任何确认无事件值。对于准确钟点支持的同日部分报告，已取得的部分记录也不会把整个当日认证为完整。

## 历史版本没有被绕过

E02 原报告为 `latest_snapshot_only`。E03 默认严格拒绝已经可能参与决策的弱版本；可以明确传 `allow_weak_vintage=True` 做受限探索，但输出保留 `lhb_vintage_warning` 和每条关联的版本政策。后来才发生或当前尚不可知的弱版本不会影响更早的决定。

本次本机切片明确选择了这个探索开关，并验证默认拒绝确实发生。没有宣称原始公告历史已恢复。

## 怎么调用

```python
from src.alpharesearch.panel import attach_events

result = attach_events(
    membership,       # 日期、股票、明确决策时间；自己决定研究名单
    original_reports, # E02 reports.parquet；所有原窗口保留
    market_calendar,  # 交易日历的有序、无重复日期列表
    universe_id="declared_membership_v1",
    window_sessions=20,
    allow_weak_vintage=True,  # 当前旧归档探索要明确承认此限制
    max_links=1_000_000,
)
panel = result.panel  # 每只股票仍在；缺失及来源限制保留
links = result.links  # 样本 ID × 原报告 ID，供 E05 关联席位
```

关联先计数，超过链接预算则在大数组构造前失败，要求按日期分块。没有一次性枚举“所有股票×所有原报告”的笛卡尔积。

## 本机真实验收

2024-01-03 至 2024-02-09，共 27 个决策日，5,111 只股票的 137,772 行已有行情键全部保留，得到 31,351 条可知报告关联；11,389 行有已知事件，126,383 行因覆盖未经足够认证而保留未知，确认无事件数为 0。

该名单是**已有行情键的工程切片**，不是经过可成交/ST/IPO/停牌核查的正式策略名单。股票个数不能当作当日所有可交易股票的证明。

真实关联、默认弱版本拒绝和 1 月末前缀检查约耗时 48 秒。把后续行情/报告追加到 2 月，不改变 1 月末之前的数值、关联或缺失标志。23 个本包反例、加上 E01/E02 共 86 项专项检查通过；全项目 548 通过、1 跳过。没有训练模型，没有新增账户；这些数字不是收益率或预测准确率。

## 本包函数与下一步

- `CoverageProof`：明确无事件结论需要什么范围与时间证据。
- `attach_events`：验证名单/日历/时点，预算内关联全部已知报告，派生事件数量和年龄及状态。
- `EventPanel`：分别返回样本面板、原报告关联和声明的协议，后续模块不会把它们混成一张有标签的 X。

E04 建设因果板型和价格结构；E05 利用原报告关联构建集中度、HHI、净额等，逐项核查分母、分类披露、多日窗口和缺失。E07 将这些与旧 16 维一起注册。新模型与正式账户比较依赖学习/桥接协议，不从本包的关联数量推导策略成功。
