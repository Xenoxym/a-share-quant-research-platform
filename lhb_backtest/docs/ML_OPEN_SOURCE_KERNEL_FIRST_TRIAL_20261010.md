# 开源计算模块的第一次实测：能导入，取数失败，尚无数值结论

这次没有训练模型，也没有新增账户回测。我们实际加载了 Qlib 0.9.7 的两个编译扩展，随后在读取本地股票数据时停止。

## 发生了什么

我写的探针用 `000001` 等六位股票代码筛选数据，而快照中的实际代码是 `000001.SZ`。精确过滤返回了零行，最低覆盖量检查因此失败。这是我们取数条件的错误，不能解释为 Qlib 的计算错误或不兼容。两名源码复核者也没有提前发现这个数据契约问题。

已保存的导入记录显示 `rolling` 和 `expanding` 在本机 NumPy 2.4.6 上成功加载。尚未运行均值、斜率、拟合优度、残差的结果比较，不能声称这些运算正确，更不能声称完整 Qlib 后端接入完成。

## 接下来

先由两名复核者核对这次失败和原因，再创建独立接续任务。接续会修正代码后缀，先检查实际取数覆盖并保存输入身份，然后进行相同八项计算比较；最多一次、300 秒、一个数值进程、两个线程。失败仍保留，不修改生产依赖，不自动重复执行。

这一工程路线是在试用现成模块。收益研究继续以真实账户年化收益和每日最大回撤评价；排名目标训练尚未运行，Windows 可承诺空间未达到重任务准入要求。
