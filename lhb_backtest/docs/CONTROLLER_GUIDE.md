# 有界自动研究总控（V7）

总控是持久化的程序调度器，加上独立的综合裁决 Agent。它接收一组已有研究任务，自动执行研究、双复核、裁决和下一轮。它与Codex桌面左侧任务栏是两套入口：当前传输为本机已登录的Codex CLI，后台会话不保证进入桌面侧栏；工作台提供过程与结果。

## 一轮怎样运行

1. 选择1至3个待领取或待复核任务，设置并发1至3、轮数1至5、调用上限3至40、单次及总时限。研究问题仍必须有依据、成功标准、停止标准。相同任务不能同时加入两个活跃总控。
2. 待领取任务先给独立研究者。总控领取并续租，研究者在独立目录内研究；回测必须经过原有register/run。最终结构化报告由总控验证、提交，不能只有一句“完成”。待复核任务直接进入下一步。
3. 两名新会话分别复核方法和数据：双方不读对方意见，不参与原研究。只读查证后提供接受、修订或暂缓建议及阻断项。`accept`表示接受限定范围内的结论，包括负面结论，不表示策略有效。
4. 新的综合裁决会话读取全部研究及双方意见。程序强制：阻断未解决只能修订或暂缓；继续必须提出新问题、成功和停止标准，不能自行增加父任务实验预算。
5. `revise`退回原任务；`continue`原子建立父子任务。剩余预算足够时自动进入下一轮。`stop`收束当前设计，`defer`等待新证据。两者都保留结论进入共同记忆。预算不足则保留排队任务，不能把预算到达称为研究已完成。

每个Agent有不同会话ID、prompt、输入上下文、结构化最终结果、事件日志、错误日志与结果哈希。同一模型的独立会话仍可能有共同偏差；这不是外部机构认证。综合判断与确定性文件核验分别记录。

## 操作

工作台“自动研究总控”支持建立、启动、查看和停止；“研究任务与交接”保留原手工接口。启动使用本机Codex登录，继承本机模型和思考设置，无需浏览器保存API密钥。优先使用桌面捆绑CLI；可设置`RESEARCH_CODEX_EXECUTABLE`显式选择支持本协议的版本。初次环境错误会显示需要处理，不会无限重试。

CLI从`lhb_backtest`运行：

```powershell
..\.venv\Scripts\python.exe tools/controller.py create --file campaign.json
..\.venv\Scripts\python.exe tools/controller.py run campaign-实际编号
..\.venv\Scripts\python.exe tools/controller.py show campaign-实际编号
..\.venv\Scripts\python.exe tools/controller.py stop campaign-实际编号
```

`campaign.json`：

```json
{
  "title": "区分状态信息与交易映射",
  "task_ids": ["task-实际编号"],
  "max_parallel": 2,
  "max_rounds": 2,
  "max_calls": 12,
  "job_timeout_seconds": 900,
  "wall_seconds": 3600
}
```

一项新研究通常4次调用，已有成果验收3次；多项研究共用一次综合裁决。登记失败与CLI启动失败也保留并占调用名额。token为结束后CLI报告值，不是实时金额预算。已停止/收束总控不会通过再次点击偷偷重启。

有明确工程修复且所有Agent进程已收取后，可`retry <编号> --reason "修复依据"`。保留原调用与总时间上限、进入下一轮，不能无限重置预算。总控进程遭强杀时，锁与running记录保留；须先检查PID、日志和子进程，不能盲目删除锁或重复执行。普通失败由程序收取、释放研究租约；CLI故障不自动认定研究结论有效。

## 零新增回测的分析成果

初筛发现无预测增量时，不应为了提交而补跑无用回测。`tools/research.py attach --session ... --file evidence.json`允许导入分析包：

```json
{"path":"research/某次分析", "kind":"feature_analysis", "summary":"证据与原作者说明"}
```

类型为`feature_analysis`或`reused_evidence`。必须有有效租约；只从项目research目录或总控工作目录导入。每包最多100MB、300文件，复制后按内容哈希冻结；提交和复核再次验完整性。每任务证据包数量上限等于其实验名额，但这个导入上限**不是**任意脚本的统计试验计数器。

分析包应包含运行前固定的设计、输入清单、代码、输出、环境、失败尝试及报告。当前平台将其明确标为`post_hoc_import` / `analysis_artifacts`：不保证实际事前固定、不执行任意分析脚本、不自动证明无未来信息或数值重现。独立复核应核实这些边界。原账户实验仍用冻结执行及独立对账；两类不能互相冒充。

## 当前边界

已实现真正的有限自动调用和研究闭环，需用户或外部任务启动；不是常驻无限搜索服务。没有金额级计费熔断、通用计算容器、任意分析尝试的强制计数、外部供应商真伪认证、未见日期封存或多机队列。研究者拥有独立工作目录但共享研究库，不等同操作系统级任务隔离。复核和裁决使用只读模式，公共成交和会计代码不在自动研究授权范围。

所有历史已经看过；换Agent、改特征或换任务ID不会生成新证据。停止、暂缓、发现基础设施问题都是有效产出，不以实验数或漂亮收益衡量总控质量。
