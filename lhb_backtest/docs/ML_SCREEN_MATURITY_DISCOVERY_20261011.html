1. 我们原本应该给模型什么？

算出特征表每只股票，每个决策日，一行X
训练模型一起利用多列预测后来收益Y
预测并选股固定相同持仓规则
计算账户收益、每日回撤、对照

当前：新64列只算完训练期；它们还没一起进入模型。逐列买前10股是额外诊断。

每一行代表“某个决策日的一只股票”。原来有68列输入，现在又设计了64个公式；每个公式为这一行产生一个新数字。所以完整方案可以是 原68列＋新64列＝132列输入 X，旁边另放我们希望模型学会预测的收益 Y。

下面只是说明表格形状，数字不是实测结果；“原68列”在真实文件中是68个独立列。

决策日 股票 原68列信息 新特征1 新特征2 …… 新特征64 后来实际收益 Y
某个周五 股票A 各种数值 0.32 -0.15 …… 0.07 +2%
同一个周五 股票B 各种数值 -0.12 0.40 …… -0.03 -1%

例如第一个新公式，把“当天涨幅在股票中的排名”和“近期相对成交量的排名”组合起来。它输出一个数字，不负责训练模型。64个公式就是64种这样的加工方法，并没有训练64个模型。

原68列的实际构成：16项价量、20项较早保存的Alpha公式、8项板型、12项龙虎榜、8项财务、4项市场信息。新64列用排名、相乘、条件切换等方法，进一步组合这些已有信息。

然后模型一次读取这一行的多列 X，学习怎样利用它们预测 Y。树可以学习条件和交互，其他模型也可有各自的使用方式。一个特征单独选股不赚钱，不等于它放进多变量模型后没有帮助。 反过来，增加特征也不保证提高效果，所以最终要做同数据、同模型的对照。

当前数据准备还没全部做完：这批新64列只计算了2020—2022年的训练期；2023—2026年预测期的新64列还没有正式计算，132列的新模型也没有训练。原68列已经用于实际训练和账户计算。

2. 我额外加的“筛选”到底在做什么？

以新特征1为例，程序没有训练任何机器学习模型，而是直接假设：这个数字越大的股票越值得买。

每个周决策日，它按这一列给股票排序，选分数最高的10只，每只占10%；查看从计划买入开盘到下一次调仓开盘的收益，再把各周结果连起来。它对64列分别做这件事，同时记录排序相关性等诊断。

接着，我设置了“每类公式最多挑1列”的规则。64列分成8类，因此最多挑8列，准备以后再放进模型。

这就是旧报告的“筛选比较”：比较每个特征单独用来选股时的粗略收益表现，挑出少数列。 它包含选股和收益评价，已经超出了检查数据缺失、单位和时间是否正确的范围。它也没有计算完整真实账户的交易、费用和每日持仓。

当时这样安排，是想先用较便宜的办法缩小后续试验规模。但本批只有64列，直接进行多变量对照值得优先做。尤其模型可能利用特征之间的关系，我不该把单列选股表现当成所有模型输入的必经条件。

3. “收益未知”不是今天查不到股价

我们在回放历史，并且固定：假装站在2023年1月5日15:30（北京时间），训练模型，随后检验2023年以后的表现。 今天虽然已经有2023年1月9日的历史股价，但这次训练不能用它，否则就把检验阶段的信息提前给了模型。

现在看出问题的那一行：

日期（北京时间） 这条样本发生什么
2022-12-30 收盘后 输入 X 已经可以计算
2023-01-03 开盘 计划买入，开始计算持有收益
2023-01-05 15:30 本次规定的训练信息截止时间
2023-01-09 开盘 计划下次调仓；这条 Y 才走完它要预测的区间

比如买入价10元，下一次调仓开盘价10.20元，Y就是+2%。要知道这个+2%，必须允许使用1月9日的价格。假装站在1月5日时，程序应该把这条 Y 标为“不能用于本次训练和收益评价”。

所以，原报告的“收益结束日”就是计算这一条收益时所使用的终点价格日期。“未知”表示按训练时间不允许用，并不表示数据库里没有这个历史价格。

多算这一周的 X 没有问题。错在程序还要求用这一周给每个特征的选股表现打分，而这一周的 Y 被正确地禁止使用。

4. 代码为什么把56列淘汰，却让8列通过？

错误由两段代码接在一起产生：前面按“决策日期属于2020—2022年”纳入了12月30日；后面正确地把超过1月5日才可知道的 Y 标成未知。但是计算每周选股收益的循环，仍然跑了12月30日这一周。

这时64列出现了两种情况：

那一周 56列普通组合特征 8列使用旧Alpha的组合特征
能否算出 X？ 每列都有足够股票可以计算，约246至2731只；不是每个股票都完整 所依赖的旧Alpha文件没有这一周，所有股票都算不出这8列
模拟买了什么？ 每列都选了10只股票 一只也没选，程序把资金留为现金
能否计算当周结果？ 选中的10只都需要1月9日价格，本次不能使用，因此记为未知 没买股票，程序对空的股票集合求和，结果是0；现金收益记0
原规则怎样处理？ 有一周结果未知，就把整列的选股测试判为“不完整”并淘汰 当周结果是0，整列的测试仍“完整”，允许参加后续比较

这8列为什么没 X，有确切原因：它们依赖较早保存的20项Alpha，那个来源文件的训练数据只覆盖到2022-12-23，预测数据从2023-01-06开始，中间没有2022-12-30。那8个新公式用到了这些旧值，缺失就传到了新列。这里不是公式算错，也不是所有行情数据突然丢失。

这也解释了“为什么缺数据反而通过”：所谓完整性检查，是这条简化选股收益序列能不能一直算下去，并不是特征表有没有缺值。 缺 X 导致“不买”，不买的结果被算成0；有 X 的56列真的模拟买了股票，反而碰上了不允许使用的未来结果。

最后那一周本来就不该参加任何一列的训练收益比较。因此这个淘汰结果反映的是程序处理不同，并没有回答哪种特征更有用。

5. “原来选出的1项”是哪一项？什么时候选的？

它是本轮程序于 2026年10月11日18:43—18:54（纽约时间） 运行这次筛选后留下的一列，名字是 prior_alpha_context_04。没有保存挑选发生的精确秒数，所以这里用登记至结果完成的区间。

它不是一只股票，也不是一个已经训练好的模型。大意是：把三项旧的市场环境类Alpha排名取平均，再与当日振幅排名组合，得到一个新特征数字。

56列退出后，只剩下8个同类公式参加比较；我又规定每类最多保留1列，所以最后只留下了这一列。旧报告中的“原来”，指的就是上一次给你发报告之前的这次程序结果，没有别的隐藏历史。

这列数据仍然可以用于研究，但这次错误的比较不能证明它优于其余63列。其余56列的已计算数值也仍在，不能据此把它们从所有模型试验中删掉。

6. 能不能修？为什么还没修？

能修，核心时间逻辑不复杂，也不需要你补数据。 在计算训练收益前，先统一确定所有公式共同使用的周：收益终点必须早于固定训练截止时间。本例应该使用153个可以评价的周，而不是154个。12月30日的 X 可以保留，但不要强迫它参加这次训练收益评分。

还要保留另一条正确规则：在一个本来已经可以评价的周，如果选中股票的结果确实缺失，仍记为未知；不能悄悄改买另一只股票或填成0。

为什么一开始没发现？我把“保留完整决策日期”和“禁止使用晚于训练截止的结果”分别实现了，却没有让收益比较使用同一个可评价日期范围。原测试还检查了“未完成的收益应当判为未知”，但没有检查另一类公式因为缺 X 持有现金而逃过淘汰的组合情形。测试通过没有证明这个研究评价规则正确。这是我的实现和测试设计问题。

还需要修正研究路线：单列选股评价作为诊断保留；不能要求所有特征先单独赚钱，才允许模型使用。 应先准备全部64列的预测数据，用原68列和132列做真正的模型对照，再讨论是否有必要筛掉某些列。

这里仍有工程工作没完成。已有预测接口草稿只打算接少数筛选列，且依赖原任务结构；“全部固定64列”需要明确接线。当前学习程序的矩阵上限是1亿个数值单元，本批933284行×132列需要123193488个；旧实验还把列数上限设为128。因此要另行声明容量并修正读取或分块方式，不能假装改一下列名就已经能跑。它是现有程序的容量约束，不是132列在机器学习原理上不可行。

8. 接下来应优先交付什么？

主线应回到你提出的流程：全部64列的训练与预测数据 → 原68列/132列的同模型对照 → 股票分数 → 相同持仓规则的账户 → 含费收益和每日回撤。 再扩展其他模型，才能知道新信息是否有帮助、不同模型是否能利用它。
