# 这次新增代码怎样把模型变成账户

从工作台或CLI执行一次登记运行后，`runner.run`看到study=complete，把工作交给`study.run_study`。它不直接下券商订单，调用的是本项目的历史资金账户引擎。

**一次完整顺序：**

1. `contracts.completion_proposal`写下日期、原基准、固定问题与时限，`ml_experiments.register`把研究矩阵、全部ML与账户源码、环境及快照哈希冻结。
2. `dataset.build_panel(inference=True)`从历史日K计算16个汇总X，同时保留最后未来还未知的周。它与原面板的共同X逐行核对。
3. `study_data.open_labels`独立建立下一开盘到下一周开盘的Y。`label_relative`减同日候选平均；股票代码、日期、Y没有进入X。
4. `Fits.fit`仅用截止前成熟标签训练。`SimpleImputer`只从这些行算中位数；岭回归的`StandardScaler`也只从训练行学统计量。
5. 原来的两个模型直接加载并核验既有评分。新目标、加市值、四组删除及打乱Y分别训练。岭回归求解平方误差加正则；提升树逐轮拟合损失梯度，使用80轮/最多7叶/最小200行等固定约束。
6. 三个岭参数及三个树配置只在2023比较RankIC，选定者再用截至2023成熟标签拟合。年度对照在每年开始前用截至上年末的成熟标签拟合。所有20次新拟合保存，重复配置复用同一个fit_id。
7. `Fits.predict`对每个当周股票输出分数。`score_decisions`排序取100只；它没有删掉未来不明的股票，也没有在小市值100只内再筛。
8. `technical.runner.run(prepared=...)`拿选股目标、周日历和市场数据调用原`portfolio.simulate`。它真实计算目标股数、事前资金、委托、成交、持仓、现金与应收分红。每个策略分别跑配置费用和零费用。
9. `tools.verify_technical.audit`用保存流水重新核对每一天现金和股数，并复算每笔开盘价与费用。`study_audit.audit_study`再核对学习时间边界、预测/指标/选股与所有关联清单。
10. `study_report.render_report`写报告；工作台读取result.json，打开19个原生账户。研究任务凭据提交结论后撤销，等待另一角色复核。

**参数与指标究竟什么关系：** `alpha`、叶数、轮数等是拟合之前设定的超参数；模型内部系数或树的分裂/叶值由训练Y和平方损失学到。参数候选的选择分数是验证期RankIC。最终账户年化不是训练损失，没有对资金曲线反向传播。

**输出的位置：** 父运行`20261003T195515-13624598`有panel、open_labels、predictions、fits、assignments、tuning、模型及account_index。子账户各有equity、positions、orders、fills、ledger、targets、warnings；这些都在data/technical，不是示意数据。全体94万行是面板规模，独立日期少得多，不能当94万独立金融样本。

## src/mlresearch/study.py

- `study_plan`，第43行：运行前固定所有19个策略、参数候选、训练规则、资金和次数预算。它是登记输入的一部分，不根据测试结果改。
- `Fits`，第73行：保存并缓存每个唯一的模型、X白名单、成熟标签截止、参数和状态。不是账户；同一默认模型被多个对照复用。
- `__init__`，第74行：建立当前运行的模型目录和内部账本，保存面板、开盘标签、配置及进度回调。
- `save`，第79行：把全部拟合状态写入fits.json，包括仍运行与失败的状态。
- `fit`，第82行：只取决策日在过去、标签已在cutoff前成熟且可观测的训练行。中位数填补在这些行拟合；岭回归加标准化，树关闭随机早停。模型拟合后保存序列化文件和哈希。
- `predict`，第123行：把某个已保存模型用于全候选或指定年份的X。只transform与predict，不用预测日期的Y再次拟合。
- `run_study`，第129行：整个顺序的总入口：核对冻结输入→构建X/Y→复用原模型→固定实验/验证选择/逐年拟合→预测→学习诊断→19个原生账户→审计→清单和报告。
- `assign`，第173行：把指定参数/截止的拟合绑定到某策略列或年度片段。将fit_id与预测日期保存到assignments.json，年度模型不会回填此前历史。

## src/mlresearch/study_data.py

- `open_labels`，第9行：为每个周信号确定下一开盘和下一次周调仓开盘，按参考前收衔接区间价格。未来只用来建立Y；缺行情记未知，不删掉候选股票。
- `fixed_scores`，第41行：给相同名单生成三个独立对照：市值越小分越高、5日跌得越多分越高、同seed与代码固定哈希分数。
- `size_buckets`，第47行：在当周完整名单内按当时公告股本估算市值稳定分为十组；不使用未来涨跌。
- `balanced_score`，第55行：先在每个规模组按模型或随机评分排名，再交错组排序，让Top100来自每组10只。
- `score_decisions`，第62行：把全部当时评分降序排列，用代码打破同分，取100只，设置每只0.98%目标及次日执行。未来标签未知也可入选。这里只做选股目标，实际成交由账户引擎做。

## src/mlresearch/study_evaluation.py

- `signal_metrics`，第9行：每个周和策略计算排序相关、Top100相对池、均方误差与覆盖。阶段末端不成熟的Y不进入学习评价；预测及账户中仍保留。年度/调参模型只报告后续测试学习指标。
- `select_validation`，第40行：只用2023验证期内已成熟标签算每周RankIC，再日期等权平均。这个分数选择超参，测试期输入与Y不参与。
- `exposure_diagnostics`，第47行：逐周保存选中股票的规模、量额、波动、近期收益；计算规模组内相关及线性残差相关。它是解释结果的诊断，不是去改预测或做行业中性化。
- `account_statistics`，第84行：从实际逐日权益计算零利率夏普、每个年份累计收益/回撤；和相同费用的小市值按周配对，给平均差的4周块区间。

## src/mlresearch/study_audit.py

- `read`，第18行：读取本机已生成的JSON；它是核查器的小辅助函数。
- `verify_links`，第22行：父清单还要检查原模型和19个子账户文件。核对账户归属与父预测哈希，防止仅父目录完整而关联账户被改。
- `audit_study`，第42行：对版本、X白名单、标签成熟截止、填补中位数、保存模型预测、标签公式、验证选择、学习指标和选股目标重新核对，并汇总19账户的现金/股数/价格/费用审计。没有重新训练全部模型或做独立投资复核。
