# 新特征公式怎么表示：E08表达式合同

这一步建立了“表达式的检查器”，还没有建立数值计算器。它允许我们明确说出怎样组合价格、成交量、龙虎榜、财务和市场特征，然后在运行前拒绝明显错误。E09才把合法表达式放到日期×股票数据上计算；再往后才是筛选、训练、账户收益与回撤验证。

## 用一个例子说明

假设我们想研究：“最近5个交易日跌得较多，而且今天成交量相对过去20日放大”的股票是否有后续反弹机会。可以写成下面的结构：

```text
rank(-delta(close, 5)) × rank(volume / mean(volume, 20))
```

这里只提出假设，并没有断言这样的股票会赚钱。`close`是未复权的每日收盘价；`delta(close,5)`是今天减去五个交易日前的收盘价，负号让下跌对应较大数值。`volume / mean(volume,20)`是相对成交量。`rank`按当天明确的股票名单排序，输出无量纲分数。两个排名相乘也是无量纲分数。

这个例子也有经济局限：绝对价格差会受股票价格水平影响，未复权价格差会混入权益变化。编译器不会替研究者证明假设合理，也不会把它当作已验证Alpha。可以另外定义相对收益版本，分别登记、验证，而不是悄悄修改公式。

```mermaid

    A[已登记的基础或二次特征] --> B[结构化公式 AST]
    B --> C[检查特征版本、单位、数据域、历史窗口与复杂度]

```

## 新增哪些输入

`features/primitives.py`提供11项明确的日线输入：开、高、低、收、前收、上下限价、成交股数、成交金额、来源限价有效标志、正成交量观察标志。股价单位是人民币/股，股数是股，金额是人民币。仍依赖上游的单位声明，不把这次封装称作独立供应商审计。

有真实成交量0时，这个0保留；供应商仍提供的OHLC也可能保留，同时正成交量标志为0。它说明数据里有报告价格，不能证明当天可以买卖。来源限价标志为真也不保证限价数值合理；两者单独检查。未知限价不靠今天的ST名称或固定百分比补造。未来收益字段不在输入白名单内。

报告价格使用声明的收盘后60秒可用规则，不是逐笔行情或实测发布延迟。未复权价格的跨日比较仍可能受到除权影响。

## 检查器具体拒绝什么

- `close + amount`：人民币/股与人民币不能直接相加。
- `log(close)`：对带价格单位的数直接取对数被拒绝；可以先构造无量纲比值。
- `lag(close,-1)`：向未来取值被拒绝；所有滞后只允许非负整数交易日。
- 原始龙虎榜报告直接参与每日股票滚动：报告域不是日期×股票域，要先经过时点投影。
- 每天一个市场数直接混进每日股票数：要明确`broadcast`，说明我们在同一天各股票使用同一个市场背景。
- 未登记、同名多版本但未选版本、参数缺失/多余、错误子节点数量、过深/过大的公式。
- Python代码字符串：不接受`eval`，只接受白名单结构化JSON节点。

单位检查主要是物理维度检查。比例、对数收益、计数、二元标志都是无量纲，但不因此具有相同经济含义；年报年龄“天数计数”也不自动成为连续时间秒数。`where`允许无量纲数作为条件，后续计算器应明确非零为真、缺失为未知。它不能检查所有经济合理性。

默认限制为127个节点、12层、额外252个历史交易日，以及有限的常数范围。滚动窗口至少2日；常数不能是NaN或无穷。窗口限制是公式在已计算特征之外追加的历史需求：对已有60日特征再取20日均值，不代表总原始历史只需要19日。

## 版本、身份和代码入口

| 入口 | 用来做什么 |
|---|---|
| `daily_primitives(...)` | 白名单日线观察→数值、单位、缺失原因、时点及来源 |
| `definitions_for_block(...)` | 将11个输入登记为`daily.*`定义 |
| `Expr.ref/const/call` | 明确构造引用、常数和操作节点 |
| `Expr.from_dict(...)` | 从有限大小的结构化JSON加载；不执行文本代码 |
| `compile_expression(...)` | 绑定特征版本、检查单位/域/历史与复杂度，生成内容身份 |
| `verify_compiled(...)` | 重新编译保存的合同，发现公式、注册表或身份变化 |

编译结果包含绑定的特征定义ID、注册表版本、节点数量、深度、单位维度、数据域及额外历史需求。公式ID由这些合同内容决定。相同公式在相同注册表内稳定；注册表增加版本后，旧保存合同不会悄悄变成新输入。

这一步不做代数等价去重、不做遗传搜索、不训练参数，也不优化收益。比如`a+b`与`b+a`目前可以有不同ID；共享子表达式与缓存由后续阶段处理。

## 与公开研究的关系

[101 Formulaic Alphas原论文](https://arxiv.org/abs/1601.00991)说明可以用有限算子组合表达可研究的信号，为这里的表示方式提供启发；不能由此推断这些公式在本机A股样本或近过去有效。[Qlib官方算子实现](https://github.com/microsoft/qlib/blob/main/qlib/data/ops.py)也使用引用、滚动和组合；其通用接口允许负滞后等用途，我们这里的预测特征合同明确拒绝未来引用。这里没有完整复制Alpha101、Alpha158或认证其收益。

## 当前验收与下一步

专项检查覆盖真实零成交、无效价格/限价、恶意文本、未来引用、混单位/混数据域、复杂度预算、版本歧义和保存合同篡改。有限真实切片用于核查11项输入、公式合同和未来前缀稳定；具体资源和数量记录在建设进度中。

下一阶段数值算子必须使用完整交易日历，不能把停牌缺行跨过去当作连续窗口；横截面排序必须限定当时明确的名单；缺失、未可知和数学未定义要继续区分。算子跑通之后仍要做正式批次登记、样本外训练和统一账户对比。这些是策略验证的前提，不能用工程通过代替盈利结论。
