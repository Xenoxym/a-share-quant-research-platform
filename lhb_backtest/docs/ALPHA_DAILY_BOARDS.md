# E04：从日 K 构造价格结构与因果板型

本包新增 `src/alpharesearch/features/boards.py` 和 `features/base.py`，构建 **29 个明确含义的特征**。不再只依赖最初 16 维，也没有为了增加数量枚举不同 MACD 参数。现有模型还没有自动使用这些新列；收益和回撤比较留到完整学习/账户接口。

## 看一只股票的两天

假设前一交易日已经确认收盘没有涨停，来源给出的有效涨停价为 11 元。

周一：开盘 10、最高 11、最低 10、收盘 11，且有成交。我们知道：当天触及涨停、收盘在涨停价、四个价格并不相同，所以不是价格全程相同的板；上下影线都为零，实体占整个日内区间，当前已确认连板为 1。

周二：来源的有效涨停价变成 12.10，开高低收全是 12.10，且有成交。我们知道：四价相同且在涨停价，当前已确认连板为 2；日内区间为零，影线占区间比例在数学上没有定义，因此保留缺失。不能为了方便给它一个假 0。

输入的限价来自逐日、已标记有效的来源字段。这个例子不把 10% 当成所有股票、所有历史制度的通用规则。

**如果只从周二开始取得数据，看到一个涨停，只能确认当前观察到至少 1 板；不知道周一是否已经涨停。** 此时精确连板次数缺失，下界为 1。系统不会等未来连板结束后，把最终 5 板倒填到周二。

## 29 个特征分别是什么

| 组 | 数量 | 含义 |
|---|---:|---|
| 蜡烛结构与跳空 | 6 | 上影线比例、下影线比例、实体绝对比例、实体方向、零区间、开盘相对来源前收的跳空 |
| 行情间隔 | 1 | 上一条行情到当前隔了多少市场交易日；周末不算缺口 |
| 已观察的板型端点/触及 | 13 | 开盘/收盘在上下限、触及上下限、四价同在上下限、同日触及两端、触限后收于内部、上限开下限收及反向 |
| 限价距离 | 3 | 收盘距上下限、上下限跨度，均用来源前收归一化 |
| 当前连板 | 4 | 上下限收盘的精确连续次数与已观察下界分别记录 |
| 已观察事件年龄 | 2 | 距上一次观察到上下限收盘的市场交易日数 |

上影线比例 = `(最高 - max(开盘, 收盘)) / (最高 - 最低)`；下影线比例和实体比例同样由这一天的四个价格构成。合法非零区间的三个比例之和为 1。

Qlib 官方 Alpha158 实现提供了影线、实体和其他日 K 结构表达，启发了本包。我们没有导入完整 Alpha158，也没有照搬其零分母处理；来源代码不是本项目收益已经验证的证据。[Qlib 官方实现](https://github.com/microsoft/qlib/blob/main/qlib/contrib/data/loader.py)

## “天地板”能知道多少

日 K 可以检查同日最高、最低分别触及两端，也能看开盘/收盘的端点组合。无法从 OHLC 确定盘中先触及哪端、反复打开几次、封多久、封单有多大或排队成交机会。本包采用 `hit_both_limits`、`upper_open_lower_close` 等明确可观察名称，不制造缺失的盘中顺序。

四价同在限价的识别还要求成交量为正；零成交或无成交量时，不能把填充的日行情当作真实“一字板”。

## 连板和缺失怎么处理

采用市场交易日连续性。来源日历不连续、某天限价未知或没有有效成交时，后续连续次数的精确起点保持未知；新的有效非涨停收盘才能建立下一段的精确边界。停牌等缺口可以有别的连板定义，本版本明确不跨未知市场日期认证连续，保留单独的间隔特征供后续研究。

“距上次观察到涨停”只表示有证据的最后一次事件，并不证明缺失期间没有另一次涨停。名字与缺失原因保留这个边界。

- OHLC 矛盾或偏离声明价格网格：无效记录。
- 来源限价无有效标记、制度/状态未知：保持未知，不从当前 ST 名称或固定涨幅推断。
- 合法零区间导致比例分母为零：`undefined_value`；新增这个缺失原因，区别于数据错误。
- 起始历史不够：精确连板缺失，观察下界另列。

金额为人民币、价格网格由调用方明确声明；默认 0.01 元。上交所现行规则给出 A 股申报价格的 0.01 元单位，但本包使用的是原字段的有效性，不拿当前规则重建所有历史限价。[上交所官方规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/trade/universal/c/c_20260424_10816492.shtml)

## X 在什么时候可用

本包是完整日 K 特征，默认声明观察结束为上海 15:00、可用时间为 15:01。这个 60 秒延迟是研究假设，不是实测供应商延迟；可以明确传入别的延迟。下午收盘形态不能给上午决定使用，后续训练/账户层要按 `known_at` 检查。

`FeatureBlock` 分开提供数值、逐特征缺失原因、单位与来源/版本/可用规则。它检查键、形状、有限数、二值/计数、数值与缺失是否相符，拒绝额外 Y 列、错配行和没有时区的钟点。大面板按列核查，不为每行创建 Python 标量对象。

## 本机真实验证

从 2023-10-01 读取含热身的完整切片，共 447,654 行，其中纯热身为 309,882 行；检查 2024-01-03 至 2024-02-09 的 137,772 行、5,111 只股票；全部与 E03 工程名单一对一关联，特征可用时间不晚于 15:10 的决定。

该段观察到 1,686 次有效涨停收盘、100 次四价同在上限；4,041 行因限价/状态或无有效成交保持未知。另有 30 行的精确涨停连板起点仍不确定；370 行的影线比例因合法零区间未定义。这些是数据/特征统计，不是买入次数或收益。

加入 2 月的后续行情不会改变 1 月末之前的数值、原因或连板结果。单进程真实构造与两次前缀/接口核查约 37 秒，0.2 秒采样的进程树峰值工作集约 1.27 GB（以首轮测量计，新版另有独立资源记录）；库线程设为 2。这次切片测量不能外推为 8 百万行全量吞吐验收。

23 个本包反例、加上 E01–E03 共 109 项专项检查通过；全项目新版 571 通过、1 跳过。末轮算术检查曾发现同分币价格不同浮点表示产生约 1e-16 的假距离/跳空，已统一有效价格网格并保存四项失败记录；新版真实切片和完整回归复核通过。零新增真实市场训练、零新增账户；数据和大证据仅保留本机。

## 怎样用、代码各负责什么

```python
from src.alpharesearch.features.boards import price_board_features

block = price_board_features(
    historical_daily_bars, market_calendar,
    source_id="declared_daily_source",
    version_id="frozen_source_hash",
    available_delay_seconds=60,
    tick_size=0.01,
)
X_values = block.values      # 日期、股票、观察/可用时间与 29 个数值
missing = block.missing      # 相同键、每列一个明确原因
units = block.units          # ratio / binary / count
```

`price_board_features` 构造当日结构、有效限价状态和价格网格，按股票沿时间向前处理；`_streak` 只携带已经观察到的过去，分别输出精确次数、下界和年龄；`FeatureBlock.validate` 负责跨数据包的数值/单位/缺失/时点合同。
