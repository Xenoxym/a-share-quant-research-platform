用一个具体故事解释

假设研究程序拿到每只股票的输入X，把它交给神经网络，网络输出一个预计的未来收益分数。想真正使用这个分数，程序除了要会训练，还必须会保存模型、恢复同一个模型、核对实际训练用了哪些数据和参数，以及拒绝伪造的训练记录。这次补齐了这些衔接。

为了检验程序，我们造了99行数据，每行只有2个原始输入。按训练时间和标签成熟时间，只能拿其中39行训练；20行训练期数据的答案还没到公布时间，所以不能学习；另外40行用于预测。它们是检查程序的合成样本，不是99只A股或行情结论。缺失处理会给2个原始输入再加2个缺失标记，总计4列送入模型。

这一次微型模型有8个隐藏单元，最多训练3轮；正式行情候选计划采用32个隐藏单元、20轮，仍未运行。隐藏单元可以把多个输入组合起来，例如一项输入高、另一项输入低时输出更高分。这种组合有没有投资价值，需要下一阶段账户检验，不能由小测试证明。

改了哪些代码，为何必须一起改

  • models.py：接入已在隔离环境验收的MLP。训练期计算填缺值和标准化参数，支持日期权重；记录实际轮数、每轮损失和训练警告。
  • learn_output_audit.py：研究程序的核查器认识MLP的标准化与训练记录，核对字段、轮数和损失；不重新拟合模型。
  • checkpoints.py：恢复模型时，比较实际保存的模型参数、实际轮数和损失曲线与外部记录；声明与对象不一致就拒绝。
  • test_alpha_mlp_integration.py：新增13项检查。完整走一次登记→训练→保存→预测→核查，再构造被篡改记录和模型的反例。

旧的14项隔离检查及其5次合成拟合没有重跑。这次只有一次原生微型拟合，原生输出经现有核查器验证，额外审核拟合为0。父进程实际进入预测方法2次；原生进程的预测方法没有另加逐次计量，不能把计划调用上限说成实际方法体计数。

13项检查说明了什么

前三项分别检查完整原生流程、不同日期样本数下的实际等日期权重及中心化目标、未来或未成熟答案改变后准备数据不变；随后6项篡改声明，4项篡改实际保存的模型。所有反例都应被拒绝，也没有通过重新训练来修复它们。

微型训练的Y是同一天的收益减去同日平均收益，学习损失仍是加权平方误差加L2惩罚。Adam用这个损失的梯度更新神经网络；它没有直接反向传播年化收益率或最大回撤。R28会把真实行情输出转成同样的周调仓选股账户，再用净收益、回撤、分期、敞口和费用对照判断。
